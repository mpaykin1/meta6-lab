## ЗАЩИТА ОТ ПОДМЕНЫ И РЫВКОВ

ОБЩЕЕ
П0. Каждый GIF — на прозрачном фоне и сразу ПОКАЗЫВАЕТСЯ ПРЯМО В ЧАТЕ, по одному: показал → следующий. «Положил в папку» без показа в чате не считается. На картинке нет текста. По умолчанию 12–24 кадра, сторона до 320 px, файл до 1,5 МБ (если заказ не просит другого).

ЭТАЛОН
П1. ЭТАЛОН — ЗАКОН. Если к заказу приложен эталон (GIF, картинка, рисунок), до рисования выпиши 5–7 его признаков: силуэт, цвета, ключевые детали. Каждый готовый GIF положи рядом с кадром эталона того же ракурса: все признаки на месте, лишних деталей нет. Не совпало → переделать, не показывать. Признак, невидимый из данного ракурса, проверяй в видимом ракурсе, не выдумывай его.
П2. НЕ ПЕРЕРИСОВЫВАТЬ, А ОЖИВЛЯТЬ. Если в эталоне уже есть нужный ракурс (например, кадры поворота на 360°), бери этот кадр как основу и только добавляй движение и эффекты. Силуэт и краски остаются как в эталоне. Рисовать заново — только ракурс, которого в эталоне нет, и строго по признакам П1.
П3. ЦВЕТ: средний цвет непрозрачных пикселей объекта отличается от эталона не больше чем на 10 по каждому каналу RGB. Больше → подогнать.
П3а. ЕДИНЫЙ МАСШТАБ И СВЕТ: все GIF одного объекта в одном масштабе (рамка объекта в одном ракурсе отличается не больше чем на 3%, кроме кадров, где рост — само действие) и с одним источником света.

ДВИЖЕНИЕ
П4. ШОВ ЦИКЛА: разница «последний → первый кадр» не больше самой большой разницы соседних кадров. Последний кадр НЕ повторяет первый (иначе в цикле пауза). Движение — синусоида с периодом ровно в длину цикла.
П8. РОВНОЕ ДВИЖЕНИЕ: разницы соседних кадров ровные — самая маленькая не меньше трети самой большой. Почти одинаковых кадров подряд нет («шаг-пауза-шаг-пауза» запрещено). Исключение — короткое зависание, если оно и есть действие (верхняя точка прыжка), не дольше 2 кадров.
П9. ДВИЖЕНИЕ ЕСТЬ: в каждом анимированном GIF максимум разницы соседних кадров не меньше 2,0 (средняя разница пикселей по шкале 0–255). Меньше → анимации нет, переделать.
П9а. ПЛАВНОСТЬ: движение течёт — вторичное движение с задержкой (подвеска отстаёт от кузова, детали качаются позже основного тела), без телепортов и резких скачков.

ДЕЙСТВИЕ
П10. ДЕЙСТВИЕ ВИДНО С ОДНОГО ВЗГЛЯДА — то, что в названии GIF:
— прыжок: рамка объекта растёт на 12–18% в верхней точке, тень на земле отходит и бледнеет, короткое зависание, приземление с проседанием и выбросом грязи;
— свет: яркие конусы лучей длиной не меньше корпуса, мягкое аддитивное свечение; задние/постоянные огни видны во ВСЕХ кадрах; вспышка (стоп-сигнал) меняет яркость не меньше чем на 40% за цикл;
— повреждения: видны по всему объекту (несколько зон: борта, детали, каркас), не в одном месте;
— поворот: заметный крен и занос, плавный возврат.
Действие не читается → переделать.

ПРОВЕРКА ЧИСЛАМИ
П12. ЧИСЛА ТОЛЬКО ИЗ КОДА: перед показом каждого GIF запусти Python-код (Pillow), который считает: число кадров, размер, вес файла, альфу (есть прозрачность), средний цвет против эталона (П3), рамку объекта (П3а), разницу каждой пары соседних кадров (min, max), шов «последний → первый» (П4). Под GIF покажи ВЫВОД КОДА. Числа без вывода кода запрещены. «На глаз» не считается.
П13. ЗАМЕР ДЕЙСТВИЯ КОДОМ (по П10): прыжок — рост рамки в %; свет — длина лучей против длины корпуса и изменение яркости вспышки в %; повреждения — сколько зон отличаются от целой версии.
П5. Под каждым GIF — строка-итог: признаки эталона ✔/✘, ΔRGB, масштаб, шов против max, min/max соседних кадров, замер действия, размер, кадры, вес. Хоть одно ✘ → GIF не показывать.

ОШИБКИ
П6. Нашёл ошибку → исправь сам и только потом показывай; голое «нашёл ошибку» запрещено.
П7. Каждый новый пойманный тип ошибки дописывай в скилл новым правилом с примером. Так скилл учится, и ошибка не повторяется.
П14. НЕ ВЫБРАСЫВАТЬ ХОРОШЕЕ: если вышел качественный GIF, но не того объекта, — не выбрасывай. Сохрани отдельно (папка other/ или other-cars/) с понятным именем и предложи, чем он может быть в игре (враг, брошенный предмет, помощник).

## ЗАГРУЗКА И ДОКАЗАТЕЛЬСТВА

П15. ЗАГРУЗКА ЧЕРЕЗ BASE64 + ACTIONS. Бинарные файлы (GIF, PNG, ZIP) в репозиторий GitHub НЕ грузить напрямую — это блокируется. Всегда так:
 а) переведи файл в base64 одной строкой (Python: base64.b64encode(open(f,'rb').read()).decode()) и запиши текстовым файлом с тем же путём и окончанием .b64 (пример: asset-packs/incoming/<игра>/drive/01.gif.b64). Один файл — один коммит;
 б) слишком большой для одной записи → части <имя>.b64.part1, .part2… (декодер склеивает их по порядку);
 в) декодер в репозитории (.github/workflows/b64-decode.yml, текст ниже) сам превращает .b64 в настоящий файл, проверяет, что это GIF/PNG/ZIP, удаляет .b64 и коммитит.
 Перед первой загрузкой в репозиторий проверь, есть ли декодер; нет — создай его первым коммитом. Если декодер уже есть и работает — не трогай.

ТЕКСТ ДЕКОДЕРА (.github/workflows/b64-decode.yml):
```yaml
name: b64-decode
on:
  push:
    paths: ['**/*.b64', '**/*.b64.part*']
  workflow_dispatch:
permissions:
  contents: write
jobs:
  decode:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: decode
        run: |
          set -e
          for p in $(find . -name '*.b64.part1' -not -path './.git/*'); do
            base="${p%.part1}"
            ls "$base".part* | sort -V | xargs cat > "$base"
            git rm -q "$base".part*
          done
          find . -name '*.b64' -not -path './.git/*' | while read f; do
            out="${f%.b64}"
            base64 -d "$f" > "$out"
            sig=$(head -c 4 "$out" | xxd -p)
            case "$sig" in 47494638|89504e47|504b0304) ;; *) echo "НЕ GIF/PNG/ZIP: $out"; exit 1;; esac
            git rm -q "$f" 2>/dev/null || rm -f "$f"
          done
      - name: commit
        run: |
          git config user.name 'b64-bot'
          git config user.email 'b64-bot@users.noreply.github.com'
          git add -A
          git diff --cached --quiet || git commit -m 'decode binary files from base64'
          git push
```

П16. ДОКАЗАТЕЛЬСТВО = SHA КОММИТА + ССЫЛКА. «Загружено» доказывается только: ссылкой на готовый файл в репозитории, SHA коммита git (40 символов) и ссылкой на зелёный прогон Actions декодера. Контрольная сумма файла (sha256/md5) — НЕ доказательство загрузки, писать её вместо SHA коммита запрещено. Проверь, что размер файла в репозитории в байтах совпадает с исходным.
П17. ПРЕПЯТСТВИЕ — НЕ ОТЧЁТ. «Доступ заблокирован / не получилось загрузить / нет прав» — не повод остановиться и писать владельцу. Сначала перебери обходы сам: base64 + Actions (П15), части файла, GitHub API, ветка + PR. Отчёт «осталось: загрузить» допустим, только если перепробованы все обходы, и в нём точный текст каждой ошибки и что именно нужно, чтобы её снять. Владельцу ничего не поручать руками.
П18. ПЕРЕД КАЖДЫМ ОТЧЁТОМ пройди по нему и вычеркни всё, что можешь сделать сам. Остались «загрузить», «закоммитить», «проверить» → сделай, потом отчитывайся. Отчёт владельцу — только что осталось сделать, сделанное не перечислять.

## КОНВЕЙЕР

П19. ОДИН GIF ЗА РАЗ. Порядок для каждого GIF строго такой и не меняется:
 1) сделать один GIF;
 2) проверить кодом (П12–П13); не прошёл → исправить этот же GIF и проверить снова;
 3) ПОКАЗАТЬ В ЧАТЕ с выводом кода (П5);
 4) загрузить (П15) и записать строку в PROGRESS.md: номер, файл, SHA коммита, ссылка на прогон;
 5) только теперь — следующий GIF.
 Запрещено: делать или исправлять несколько GIF «пачкой», откладывать показ, грузить пачкой в конце. Если загрузка ещё идёт (ждёт Actions) — следующий GIF можно начинать, но строка в PROGRESS.md пишется сразу, как прогон стал зелёным.
П20. КОРОТКАЯ СЕССИЯ. За один ответ — не больше 3 GIF по конвейеру П19. Потом короткий отчёт (что осталось) и стоп. Владелец пишет «дальше» — следующие 3. Лучше 3 показанных и загруженных, чем 10 начатых и ни одного готового.
П21. ИСХОДНИКИ ИЩУТСЯ ОДИН РАЗ. В начале заказа найди все исходные файлы (эталон, прежние GIF) и запиши их точные пути в первую строку PROGRESS.md («Исходники: …»). При каждом следующем запуске бери пути оттуда, не ищи заново. Файла нет по пути → один раз поищи в репозитории и библиотеке, исправь путь в PROGRESS.md и иди дальше.

П22. ОДИН ЗАМЕР ДЛЯ ВСЕХ. «Разница кадров» = средняя по ВСЕМУ кадру абсолютная разница каналов R, G, B (0–255) между соседними кадрами, кадры переведены в RGB целиком (Pillow: ImageChops.difference → ImageStat.Stat(...).mean, среднее трёх каналов). Не по маске объекта, не по альфе, не по части кадра. Порог П9 (2,0) и П8 считаются только так; П4 использует ту же метрику. Замер публикации делается по файлу, СКАЧАННОМУ обратно с GitHub (raw-ссылка), а не по локальной копии. Локальные проверки — предварительные, не доказательство публикации. Сохранять точный URL и вывод. Никакого обнуления скрытых RGB, композиции на подложку или округления до сравнения с порогом.

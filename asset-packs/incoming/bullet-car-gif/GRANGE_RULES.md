## ЗАЩИТА ОТ ПОДМЕНЫ И РЫВКОВ

Обязательно для КАЖДОГО будущего заказа. Дополняет прежний стиль и проверки, не отменяет их. При повторе сначала прочитай актуальный SKILL.md и PROGRESS.md, не повторяй завершённое.

### ОБЩЕЕ
П0. Каждый GIF — на прозрачном фоне и сразу ПОКАЗЫВАЕТСЯ ПРЯМО В ЧАТЕ, по одному: показал → следующий. «Положил в папку» без показа в чате не считается. На картинке нет текста. По умолчанию 12–24 кадра, сторона до 320 px, файл до 1,5 МБ (если заказ не просит другого). Для старых утверждённых ассетов не уменьшая их без разрешения, фиксируй явно согласованное исключение. Не утверждай, что клиент воспроизвёл GIF, если это не подтверждено.

### ЭТАЛОН
П1. ЭТАЛОН — ЗАКОН. Если к заказу приложен эталон (GIF, картинка, рисунок), до рисования выпиши 5–7 его признаков: силуэт, цвета, ключевые детали. Каждый готовый GIF положи рядом с кадром эталона того же ракурса: все признаки на месте, лишних деталей нет. Не совпало → переделать, не показывать. Невидимые признаки проверяй в другом ракурсе, не выдумывай. Встроенный стилевой пример не заменяет эталон заказа.

П2. НЕ ПЕРЕРИСОВЫВАТЬ, А ОЖИВЛЯТЬ. Если в эталоне уже есть нужный ракурс (например, кадры поворота на 360°), бери этот кадр как основу и только добавляй движение и эффекты. Силуэт и краски остаются как в эталоне. Рисовать заново — только ракурс, которого в эталоне нет, и строго по признакам П1. Зафиксируй индекс кадра и SHA-256 оригинала. Нет исходника — не подменяй. Без приложенного эталона создай исходный базовый кадр нового объекта.

П3. ЦВЕТ: средний цвет непрозрачных пикселей объекта отличается от эталона не больше чем на 10 по каждому каналу RGB. Больше → подогнать. Сравнивай каждый кадр с соответствующим ракурсом, максимум абсолютных отклонений по каналам, не среднее отклонений. Для эффектов измеряй корпус отдельно по фиксированным маскам, не скрывай изменение основного материала.

П3а. ЕДИНЫЙ МАСШТАБ И СВЕТ: все GIF одного объекта в одном масштабе (размер рамки объекта в одном ракурсе отличается не больше чем на 3%, кроме кадров, где рост — само действие) и с одним источником света. Для жёсткого неподвижного ракурса действует прежняя более строгая проверка: после компенсации заданного движения bbox корпуса ≤2% (минимум 1 px округления), центр ≤2 px, IoU ≥0,95. Сравнивай соответствующие ракурсы/фазы. Проверяй белую кайму на светлом и тёмном фоне, обрезку, альфу и длительности. Световое направление подтверждай визуально, эффекты измеряй отдельно.

### ДВИЖЕНИЕ
П4. ШОВ ЦИКЛА: разница «последний → первый кадр» не больше самой большой разницы соседних кадров. Последний кадр НЕ повторяет первый (иначе в цикле пауза). Движение — синусоида с периодом ровно в длину цикла. Для циклов с несколькими фазами допустима непрерывная периодическая траектория с настоящими промежуточными кадрами. Не ухудшай соседние кадры ради прохождения порога, не меняй скорость только на шве. Метрика: среднее абсолютное различие RGBA (0–255) на объединении непрозрачных масок пары, RGB прозрачных пикселей обнулён. Одноразовый клип по заданию — без проверки замыкания.

П8. РОВНОЕ ДВИЖЕНИЕ: разницы соседних кадров ровные — самая маленькая не меньше трети самой большой. Почти одинаковых кадров подряд нет («шаг-пауза-шаг-пауза» запрещено). Исключение — короткое зависание, если оно и есть действие (верхняя точка прыжка), не дольше 2 кадров. Исключение допускается только для заранее указанных и проверенных кадров вершины прыжка, не для произвольного замедления; включай шов в проверку равномерности циклов.

П9. ДВИЖЕНИЕ ЕСТЬ: в каждом анимированном GIF максимум разницы соседних кадров не меньше 2,0 (средняя разница пикселей 0–255). Меньше → анимации нет, переделать.

П9а. ПЛАВНОСТЬ: движение течёт — вторичное движение с задержкой (подвеска отстаёт от кузова, детали качаются позже основного тела), без телепортов и резких скачков.

### ДЕЙСТВИЕ
П10. ДЕЙСТВИЕ ВИДНО С ОДНОГО ВЗГЛЯДА — то, что в названии GIF:
— прыжок: рамка объекта растёт на 12–18% в верхней точке, тень на земле отходит и бледнеет, короткое зависание, приземление с проседанием и выбросом грязи;
— свет: яркие конусы лучей длиной не меньше корпуса, мягкое аддитивное свечение; задние/постоянные огни видны во ВСЕХ кадрах; вспышка (стоп-сигнал) меняет яркость не меньше чем на 40% за цикл;
— повреждения: видны по всему объекту (несколько зон: борта, детали, каркас), не в одном месте;
— поворот: заметный крен и занос, плавный возврат.
Действие не читается → переделать. Эти признаки применяй к соответствующему действию и объекту, не навязывай автомобильные детали другим сущностям.

### ДОКАЗАТЕЛЬСТВА
П12. ЧИСЛА ТОЛЬКО ИЗ КОДА: перед показом каждого GIF запусти Python-код (Pillow), который считает: число кадров, размер, вес файла, альфу (есть прозрачность), средний цвет против эталона (П3), рамку объекта (П3а), разницу каждой пары соседних кадров (min, max), шов «последний → первый» (П4). Под GIF покажи ВЫВОД КОДА. Числа без вывода кода запрещены. «На глаз» не считается.

П13. ЗАМЕР ДЕЙСТВИЯ КОДОМ (по П10): прыжок — рост рамки в %; свет — длина лучей против длины корпуса и изменение яркости вспышки в %; повреждения — сколько зон отличаются от целой версии. Используй маски корпуса, лучей, постоянных и мигающих огней, непересекающиеся зоны повреждений, привязанные к эталону. Измеряй декодированные пиксели, не длину нарисованной маски как таковой. Для повреждений сравнивай зарегистрированную целую версию того же ракурса, минимум 3 зоны с существенным изменением (≥10% пикселей зоны с RGB MAE ≥12); для вспышки (max−min)/max ≥40%. Нет необходимых масок/ракурса — BLOCKED, не PASS. Проверяй действие визуально дополнительно.

П5. Под каждым GIF — строка-итог: признаки эталона ✔/✘, ΔRGB, масштаб, шов против max, min/max соседних кадров, замер действия, размер, кадры, вес. Хоть одно ✘ → GIF не показывать. Числовой PASS не заменяет П1 и визуальный П10.

### ОШИБКИ
П6. Нашёл ошибку → исправь сам и только потом показывай; голое «нашёл ошибку» запрещено. При реальном блокере укажи его, не фабрикуй исходник и вывод.
П7. Каждый новый пойманный тип ошибки дописывай в этот раздел новым правилом с примером. Так скилл учится, и ошибка не повторяется. Добавь исполняемую проверку; не объявляй обновлением текст текущего ответа.
П14. НЕ ВЫБРАСЫВАТЬ ХОРОШЕЕ: если вышел качественный GIF, но не того объекта, — не выбрасывай. Сохрани отдельно (папка other/) с понятным именем и предложи, чем он может быть в игре (враг, брошенный предмет, помощник). Существующую папку Bullet Car other-cars/ сохраняй.

П15. РЕМОНТ ШВА НЕ МЕНЯЕТ ИСХОДНЫЕ КАДРЫ. При заказе «исправить только рывок» сохраняй исходные кадры и длительности в исходном порядке, добавляй только промежуточные кадры в зоне шва. Сравни декодированные RGBA (без скрытого RGB) и длительности на точное равенство; новые переходы ≤ исходного внутреннего максимума. Повторное квантование старых кадров (разницы 0,825 и 0,359) было ошибкой; требуемое значение 0,0. Если новый П8 не совместим с сохранением старых кадров, не объявляй PASS и не меняй исходники без разрешения.

П16. РИТМ НЕ ПОДМЕНЯЕТСЯ ДЛИТЕЛЬНОСТЬЮ КАДРА. Проверяй длительности декодированного GIF: в обычном цикле min/max длительности ≥0,8; исключение только для явно заданного зависания до двух кадров, при этом исключённые интервалы не длиннее двух обычных кадров суммарно. Пример: равные визуальные шаги с длительностями 80/400 мс дают рывок даже при правильном П8. Не исправляй шов замедлением последнего кадра.

### ПРИМЕРЫ ОШИБОК, ИЗ КОТОРЫХ ВЗЯТЫ ПРАВИЛА (Bullet Car)
— П1/П2: вместо машины с эталона нарисованы другие (коричневый внедорожник с цепями и антенной; пикап с турелью).
— П3: машина темнее эталона (RGB ~61,52,45 против ~84,74,66).
— П4: шов цикла в 2 раза больше, чем между соседними кадрами, — рывок.
— П8: разницы «4,0 → 0,2 → 4,0 → 0,2» — машина едет толчками.
— П9: 07_drive_west — разница 0,26, машина стоит.
— П10: прыжок без подъёма (рост 6% — не видно); ночь — вместо лучей точки, стоп-сигнал не вспыхивает; повреждения 1 — только царапины на капоте.
— П12: 12_night_lights показан с разницей 0,06 при пороге 2,0 — числа писались на глаз.

### Исполнение
Запускай `scripts/check_gif.py` (Pillow, NumPy) на конечном GIF, а не на исходной сетке. Передавай эталон, индексы его кадров, маски и action-конфигурацию; `--help` описывает формат. Для прежних строгих проверок используй `--rigid`, для точного ремонта `--preserve-prefix`. Сохраняй JSON stdout, проверяй exit code, не обходи отсутствующие входы. П1 и художественный П10 проверяются визуально; код не распознаёт идентичность. При повторном заказе сначала прочитай PROGRESS.md, сохраняй фактические ссылки и SHA после каждого шага. Для Bullet Car: `asset-packs/incoming/bullet-car-gif/GRANGE_RULES.md`, `check_gif.py`, `PROGRESS.md`; не отмечай локальный файл опубликованным до подтверждения GitHub.

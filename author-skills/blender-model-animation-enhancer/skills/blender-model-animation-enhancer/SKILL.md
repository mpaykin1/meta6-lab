# Blender Model & Animation Enhancer — v1.9 (Blender + PyMeshLab + Instant Meshes + SkinTokens + Open Mocap + Rigger + Material Maker + glTF Transform + meshoptimizer + glTF Validator)


## meshoptimizer / gltfpack — v1.8 (ninth open-source integration)

Read `references/MESHOPTIMIZER_BRIDGE.md`. The project `zeux/meshoptimizer` (MIT) adds a second real, optional postprocessor **after** Blender/glTF Transform. It optimizes GLB vertex cache/fetch layout and can opt-in to compressed buffers or smaller web textures. This skill calls the official `gltfpack` native executable; it does not bundle or simulate meshoptimizer.

- `scripts/run_enhancer.py --meshoptimizer` runs **after** earlier author-approved stages. Existing `.glb` with no prior stages can be optimized standalone without Blender. `--gltf-optimize --gltf-mode safe --meshoptimizer` runs glTF Transform safe dedup/prune **then** gltfpack. Double encoding through Draco/meshopt stages is blocked.
- Default `--meshoptimizer-mode safe` requires no runtime decoder; it retains named nodes/materials/extras via `-kn -km -ke` and disables quantization via `-noq`. Optimized output must preserve skin-joint names/hierarchy, animation channels/interpolation, morphology, material assignments, and per-object game IDs. If safety validation fails, abort without a new GLB. When the safe output is larger, keep a copy of the original rather than claiming a gain.
- Modes `compressed`, `webp`, and `ktx2` require **explicit authorization** because they introduce browser decoder support and/or possibly alter appearance. Three.js Meshopt mode requires `MeshoptDecoder`; KTX2 requires `KTX2Loader` support. Never automatically compress already-approved artwork.
- `--meshoptimizer-mode simplify --meshoptimizer-ratio 0.8` is restricted to **static** scenery and removes geometry. Never run on rigged/animated characters, shape-key heroes or skinned parts. Inspect visuals before accepting.
- The upstream source download is optional via `scripts/get_official_meshoptimizer_source.sh`; a full clone and native binary are not bundled. If unavailable, report the blocker and provide prepared scripts, not fabricated model outputs.
- A structurally valid GLB is not enough for a playable game: preserve one continuous character, animated living world and fullscreen mobile portrait + landscape as required by `animated-world-guard`.

```bash
python scripts/run_enhancer.py --input character.glb --output character-web.glb \
  --gltf-optimize --gltf-mode safe --meshoptimizer --meshoptimizer-mode compressed
```


## glTF Validator — v1.9 (tenth open-source integration)

**Mandatory reading:** `references/GLTF_VALIDATOR_BRIDGE.md`. The original KhronosGroup/glTF-Validator (Apache-2.0) is a separate CLI. It verifies glTF 2.0 binary layouts, animation channels, materials, extensions and resource references. It is **not included** in this ZIP. Do not claim real validation without having executed the official binary. No separate report files are generated by the bridge.

- The same `scripts/run_enhancer.py` command automatically validates the final GLB when `gltf_validator` is installed; staged intermediate files stay private and original inputs are never overwritten.
- Use `--gltf-validation require` to enforce the external validator; `--gltf-validation auto` is default and skips the official check **only when absent**, preserving earlier structural checks; `--gltf-validation off` explicitly skips it.
- `--gltf-validator-bin /path/to/gltf_validator` selects the binary and `--gltf-validator-strict` rejects warnings as well as errors.
- It runs after meshoptimizer and glTF Transform, not before them. The existing animation/joint/material signature checks remain in force. No hidden automatic character animations or alteration of user-approved artwork.
- glTF validity does not establish game compatibility or visual fidelity; verify actual game rendering and animation separately, including phone portrait/landscape.

```bash
python scripts/run_enhancer.py --input hero.glb --output hero-validated.glb --gltf-validation require
```

## glTF Transform — v1.7 (eighth open-source integration)

Read `references/GLTF_TRANSFORM_BRIDGE.md`. Official `donmccurdy/glTF-Transform` (MIT) provides CLI post-processing for GLB / Three.js. Its npm package is an **external dependency**; source and binary are not bundled.

- Add `--gltf-optimize` to **the same** `scripts/run_enhancer.py` command to run the final GLB stage. For existing `.glb` and no other stages, Blender is not required.
- The default `--gltf-mode safe` runs `gltf-transform dedup` then `prune`, with GLB structural checks guarding armature joints, animation clips/channels, mesh links and morph targets. Does not introduce compressed-geometry decoder dependencies.
- `--gltf-mode webp|meshopt|draco|webp-meshopt` is **explicit opt-in**; Draco requires DRACOLoader, Meshopt requires MeshoptDecoder, and WebP changes image encoding and may affect author-approved visuals. Never silently add these codecs to a game.
- When other pipeline flags are present, the runner produces a temporary GLB with the existing Blender/PyMeshLab/Instant Meshes/SkinTokens/Open Mocap/Rigger/Material Maker path and runs the glTF Transform postpass **last**. Original asset is untouched and invalid optimized output is never committed.
- Retopology and PBR edits are separate, author-approved steps. glTF Transform is for finished 3D scenes with rig and clips. Never replace approved character PNG/GIF assets with code primitives.

```bash
python scripts/run_enhancer.py --input hero.glb --output hero-final.glb --gltf-optimize
```


## Material Maker — v1.6 (seventh open-source integration)

Read `references/MATERIAL_MAKER_BRIDGE.md`. Official upstream `RodZill4/material-maker`, MIT license, provides Godot-based procedural PBR authoring and native CLI `.ptex` texture export; the upstream application is an **external executable**, not included in the Skill.

- `scripts/material_maker_worker.py` invokes the real official Material Maker `--export-material --target GLTF/Plane` command or consumes already exported PBR maps; `scripts/material_maker_blender.py` applies albedo/ORM/normal/emission to the **explicitly named** mesh object using Blender's Principled BSDF, then exports GLB with skins/morphs/actions.
- Never auto-retexture an approved hero. An author must explicitly request material changes and provide a `.ptex` or PBR map directory. Only the shader/material changes; the workflow preserves source mesh geometry, bone hierarchy, vertex groups, existing action clips and original input file. A new PBR material may visibly alter appearance; user review is mandatory.
- Run this in a **separate step**, after safe PyMeshLab/Instant Meshes geometry processing, after SkinTokens rigging, and after Open Mocap/Rigger animation clips. UVs are required; Instant Meshes may remove source UVs and must be followed by an author-approved UV unwrap before texturing.
- `GLTF/Plane` output uses packed ORM (R ambient occlusion, G roughness, B metallic) plus albedo and normal. No generic GLSL reimplementation or synthetic PBR maps in the Skill. When these binaries are unavailable, do not falsely claim successful conversion.

```bash
python scripts/run_enhancer.py --input hero.glb --output hero-pbr.glb \
  --material-ptex surface.ptex --material-maker-bin /path/to/material_maker \
  --material-object HeroMesh --material-size 1024
```

With already exported PBR maps:

```bash
python scripts/run_enhancer.py --input hero.glb --output hero-pbr.glb \
  --material-textures-dir ./maps --material-object HeroMesh
```

Source download helper: `scripts/get_official_material_maker_source.sh`; file list / licensing `vendor/MaterialMaker-SOURCE.md`. Full native application and assets not bundled.

## Purpose

Turn an uploaded 3D asset into a reliably processed game-ready Blender/Three.js GLB. Use Blender's official Python `bpy` API. This skill packages original automation scripts; it **does not bundle Blender, PyMeshLab, Instant Meshes binaries, SkinTokens model weights, Rigger source, or complete upstream source trees**. A working Blender 4.5+ executable must be available in the execution environment. Do not claim that a Blender transformation was executed when the executable or input file was unavailable.

## Input and output

- Supported source files: `.glb`, `.gltf`, `.fbx`, `.obj`, `.blend`.
- Default output: a `.glb` file preserving armatures, mesh identity, materials, shape keys (where supported by exporter), and existing animation data.
- Work on a **copy**, never overwrite source. Do not generate a different character or substitute a primitive mesh. Never replace approved textures/PNG/GIF assets with procedural illustrations.
- For Blender scene `.blend` with unsupported add-ons, link libraries, or external textures, resolve dependencies before export; warn when not available.

## Do this on every task

1. Locate the user's source model. Confirm file actually exists and determine type. If there is a reference image or approved character, preserve appearance, silhouette, colors, mesh and material names; do not invent or replace missing geometry.
2. Locate Blender via `BLENDER_BIN`, PATH, or standard installation paths; if absent, state the blocker and offer the prepared script/ZIP. Do not claim output generated.
3. Use `scripts/run_enhancer.py` (CLI wrapper), which invokes `scripts/auto_enhance.py` in Blender headless mode. The default profile is **SAFE**: identity and animations remain untouched except serialization to GLB.
4. Only with explicit user request, apply `--repair-static` to non-skinned meshes (remove duplicate vertices, normalize face orientation) and `--smooth-static` to non-skinned, non-shape-key meshes. These can affect stylized shapes/shading; inspect result before accepting.
5. Only with explicit user request, enable `--polish-motion`: clamps Bezier handles on existing location/scale channels to reduce overshoot. It does not add poses, locomotion, rigging, or animations. Preserve keyframe count, rotation curves, timing and action names.
6. Export as GLB for Three.js. Where export or import cannot be validated, say so. For a game, load the exported model with `GLTFLoader` and route its animation clips through `AnimationMixer`; changes of clips may **not** change geometry or materials.
7. If the user supplies a particular character, animations for front/back/left/right, walk, idle, jump, crouch, roll, dodge, attack must reference the same character and skeleton. Do not fabricate missing clips or silently map a clip from a different hero.
8. Prefer finished files to long prose; user does not request reports or documentation.

## PyMeshLab extension (second open-source integration)

PyMeshLab is an isolated external Python dependency. Read `references/PYMESHLAB_BRIDGE.md` before using it. It supplies real triangulated-mesh geometry processing via the official `pymeshlab.MeshSet()` API, **not** a pseudo-filter. Never claim PyMeshLab ran when it was not installed.

- Use `--pymeshlab-analyze` for no-change geometry diagnostics on **all** mesh objects, including skinned assets.
- Use `--pymeshlab-clean-static` **only on explicit request** to remove duplicate vertices, duplicate faces, zero-area faces and unused vertices on eligibility-checked geometry-only objects. Meshes with textures, material slots, UVs, custom attrs, vertex colors, mixed shading, shape keys, modifiers, vertex groups or armatures remain unchanged (diagnostics only).
- The bridge sends vertex/triangle JSON to a **separate** PyMeshLab Python process, receives a validated cleaned result and returns it to Blender. This avoids conflicting native Python environments and preserves Blender's scene hierarchy. The user-owned source file is never overwritten.
- With `--pymeshlab-*` flags, require a working PyMeshLab (`python -m pip install pymeshlab numpy`) and a Blender binary; otherwise stop with an explicit error.
- Do not include native PyMeshLab/Blender binaries in the Skill and do not misrepresent linked GitHub source as a complete download. The bridge itself is original code. PyMeshLab and Blender are GPL-3.0 upstream projects.
- If the user provided a 3D file and the local executor can run Blender/PyMeshLab, process it and return the actual new GLB. Otherwise return prepared code/files, state that processing was not executed.

## Local execution

Run from this skill's folder; use absolute paths when possible:

```
python scripts/run_enhancer.py --input /path/hero.fbx --output /path/hero-enhanced.glb
python scripts/run_enhancer.py --input /path/stone.obj --output /path/stone-enhanced.glb --repair-static --smooth-static
python scripts/run_enhancer.py --input /path/hero.glb --output /path/hero-polished.glb --polish-motion
python scripts/run_enhancer.py --input /path/hero.fbx --output /path/hero-analyzed.glb --pymeshlab-analyze
python scripts/run_enhancer.py --input /path/rock.obj --output /path/rock-clean.glb --pymeshlab-clean-static
```

`run_enhancer.py` requires Python 3.9+ and a separate Blender executable. Default Blender-only mode does not need pip packages. PyMeshLab modes require a separate Python interpreter with `pymeshlab` and `numpy`. If you already run inside Blender, use `blender --background --factory-startup --python-exit-code 2 --python scripts/auto_enhance.py -- --input <file> --output <file>`.

## Quality and safety invariants

- Asset identity: same imported mesh objects, rig objects, and material slots; no primitive substitutes.
- Deformation: never apply a modifier, merge vertices or alter mesh topology on a skinned object or mesh with shape keys.
- Animation: don't replace/remove action datablocks, keyframe timings, animation clip names or character armatures; optional handle clamp only when requested.
- If a mesh contains duplicate vertices but is rigged, flag it rather than risk destroying weights/morph data.
- No made-up upgrades: Blender cannot infer detailed skin weights, a better sculpt, four view directions, or new motions from an OBJ alone without more assets/models and a separate workflow.
- Preserve approved style (e.g. INK, PS1/lo-fi, pixel 2.5D); no auto-photorealistic materials or heavy smoothing by default.
- Target Three.js browser load. GLB contains geometry, materials, animation; collision meshes and game logic remain separate.

## Instant Meshes extension (third open-source integration; v1.2)

Read `references/INSTANT_MESHES_BRIDGE.md`. This integration invokes **real upstream Instant Meshes** (`wjakob/instant-meshes`) through its verified CLI batch arguments. It is not simulated by Blender remesh modifiers.

- Default remains non-destructive; run this stage **only** on explicit user request with `--instant-retopo-static`.
- Use `--instant-meshes-bin /absolute/path/to/InstantMeshes` or environment `INSTANT_MESHES_BIN`. The binary must really exist; do not claim results if it cannot execute.
- `--instant-faces N` is optional; `0` estimates half the original triangle count (floor 100). Reject if geometry is too small.
- When `--pymeshlab-clean-static` is also requested, execute stages **PyMeshLab cleanup → Instant Meshes retopology → Blender export**, so the algorithms complement one another.
- All objects with UVs, materials, custom attributes, vertex colors, any modifiers, skinning, shape keys, animations, constraints or shared mesh data are skipped. Never change an animated character into a different geometry. For rigged heroes, this skill still only preserves and exports their original assets; proper deformation-aware retopology/weight transfer needs additional tools and review.
- The worker uses local-space temporary OBJ files; validates bounds and topology; replaces only eligible static Blender mesh datablocks without changing Blender object identity.
- Source files were inspected in the official GitHub repository (README, CLI entry point, license). The complete upstream repository and its native binary **could not be downloaded here** because the network could not resolve github.com. Do not call the original Python adapters an Instant Meshes implementation.

Example with all three tools:

```bash
python scripts/run_enhancer.py --input rock.glb --output rock-reworked.glb \
  --pymeshlab-clean-static --instant-retopo-static --instant-faces 1200 \
  --pymeshlab-python /path/to/python-with-pymeshlab \
  --instant-meshes-bin /path/to/InstantMeshes
```


## SkinTokens fourth open-source integration — v1.3

Read `references/SKINTOKENS_BRIDGE.md` before any AI rigging. Source verified in the official repo `VAST-AI-Research/SkinTokens` (MIT) at commit `273b691d35989d71cd17ff2895fdc735097b92d1`. `scripts/skintokens_worker.py` invokes the **real upstream TokenRig** CLI `demo.py --input ... --output ... --use_transfer` in a separate Python/CUDA process. Requires NVIDIA GPU >=14 GB VRAM, Python >=3.11, CUDA >=12.1 and official checkpoints. The skill's own original scripts are not a reimplementation of the neural model.

- Use only when user explicitly asks for **automatic creation of skeleton + skin weights** for an unrigged character and authorizes a materially new rig. For source with an existing rig, weights, animations or shape keys, the auto-rig pathway intentionally **rejects** the operation; do not mutate their approved character.
- `--skintokens-rig` activates separate Blender preflight -> optional PyMeshLab cleanup -> optional Instant Meshes retopo on safe static geometry -> SkinTokens rig generation -> Blender GLB output validation. Existing auto-enhancer features remain. Never turn on heavy steps without explicit request.
- Upstream `--use_transfer` requests preservation of original appearance/scale; the adapter also gates on geometry bounds, vertex/polygon counts, original UVs/material slots and valid exported skinning. Human appearance validation remains necessary. Auto-rigged output has **no invented walk, jump, crouch, roll, attack, etc. animations**.
- Never try to execute SkinTokens on CPU, hallucinate generated weights, or claim completion when model downloads/CUDA were absent.

Example:


## Open Mocap extension — v1.4 (fifth open-source integration)

Read `references/OPEN_MOCAP_BRIDGE.md` **before** running capture. This integrates upstream **Open Mocap** Blender add-on via `scripts/open_mocap_capture.py`, using the real upstream `PoseTracking.detect_pose` and offloading the video capture to Blender <=4.0. Blender >=4.5 performs the separate retarget/GLB-export step. Never run the Open Mocap addon directly inside modern Blender; its upstream README explicitly says Blender 4.0.0 or earlier only.

- Use only on explicit request for **mocap animation from a user-supplied video**. No automatic player movement/attack on idle. Preserve original character and geometry, actions, skin/weights and material identity. Capture creates a **new animation clip**, not a new hero.
- If character is unrigged: SkinTokens rig first, then Open Mocap after; if already rigged, skip SkinTokens. PyMeshLab + Instant Meshes may touch geometry only on safe unrigged static inputs, **never after rigging**.
- The Open Mocap video stage requires the real upstream source clone, correct Blender4.0 environment, OpenCV/CVZone/MediaPipe. Network failure => no claim of installed source or working capture.
- `scripts/open_mocap_retarget.py` requires existing skinning and bone map. Auto aliases support common Mixamo/Rigify names; arbitrary SkinTokens names require explicit JSON bone-map. Bad/unknown mappings must halt, not silently map to other heroes.
- No promised IK/foot grounding/reliable finger capture from the body-only stage. One-camera depth is uncertain and first frame is used as the motion baseline. Preserve user-approved visual design.
- On final GLB, reject if any previous named GLB animation is missing. The new clip is named `--mocap-clip` and is opt-in for game controls via Three.js `AnimationMixer`.

Example:

```bash
python scripts/run_enhancer.py --input hero-rigged.glb --output hero-mocap.glb \
 --mocap-video jump.mp4 --mocap-addon-dir /work/open-mocap-blender \
 --mocap-blender40 /opt/blender-4.0/blender --mocap-clip Jump
```

To use a previously recorded Open Mocap JSON (without recapturing video):

```bash
python scripts/run_enhancer.py --input hero-rigged.glb --output hero-mocap.glb \
 --mocap-landmarks captured.json --mocap-bone-map map.json --mocap-clip Walk
```

Files: `scripts/open_mocap_capture.py`, `scripts/open_mocap_retarget.py`, `scripts/open_mocap_worker.py`, `scripts/get_official_open_mocap_source.sh`, `references/OPEN_MOCAP_BRIDGE.md`.


## Rigger extension — v1.5 (sixth open-source integration)

Read `references/RIGGER_BRIDGE.md` before using. Official open source: https://github.com/asu37/Rigger (GPL-3.0-or-later); requires Blender **4.2+** and real, locally checked-out source. Obtain with `scripts/get_official_rigger_source.sh` when network is available. Do not claim that downloading or rig processing succeeded if local network or Blender is absent.

Use Rigger **after** SkinTokens or another existing rig and **after** Open Mocap's separate capture stage. Rigger's bone matcher transfers motion from an animated GLB/FBX source armature to the approved character's **existing** rig. The original geometry, materials, shape keys, vertex groups, and action clips must remain untouched; a new clip is generated and never auto-started in-game.

A mismatched source or unrecognized SkinTokens rig must NOT silently animate incorrect bones: stop unless Rigger safely maps >=3 bones or the user provides explicit `--rigger-bone-map` JSON.

```
python scripts/run_enhancer.py --input hero.glb --output hero-retargeted.glb \
  --rigger-source captured-motion.glb --rigger-dir /work/Rigger \
  --rigger-source-action Run --rigger-clip Run
```

Use optional `--rigger-controls` only on explicit request for extra animator controls, writing a **separate BLEND** in Rigger's `PRESERVE` mode. This is never a prerequisite to direct motion retarget. For an existing Rigger control-rig BLEND only, use `--rigger-game-export` for a game-ready GLB; check exported animations and mesh appearance manually before accepting in-game.

```
python scripts/run_enhancer.py --input hero.glb --output hero-controls.blend \
  --rigger-controls --rigger-dir /work/Rigger
python scripts/run_enhancer.py --input hero-controls.blend --output hero-game.glb \
  --rigger-game-export --rigger-dir /work/Rigger
```

No dependency installation from untrusted assets. Do not run unknown user-provided custom Blender scripts. The official Rigger exporter has optional custom-script execution; disable this in the bridge. No automatic animation triggered without explicit player input. Keep existing plugin URL and identity; never create a second competing plugin.

Bundled additions: `scripts/rigger_worker.py`, `scripts/rigger_blender.py`, `scripts/get_official_rigger_source.sh`, `references/RIGGER_BRIDGE.md`, `vendor/Rigger-SOURCE.md`.

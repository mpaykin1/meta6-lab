# Game Style Forge — production instructions

## Trigger
Use when the user uploads MP4/MOV/WebM/GIF gameplay and asks what gives it its appearance, which open-source projects help reproduce it, requests creation of a game in that style, or says "скачай первый / следующий опенсорс", "интегрируй" or "обнови скилл".

## Required workflow (no placeholder-only deliveries)
1. If a video is attached, locate the actual attachment bytes. Use `scripts/styleforge.py analyze INPUT --out OUTPUT`. This produces `style_profile.json` and `contact_sheet.jpg`. Inspect the contact sheet with vision. Add `semantic_notes` for scene genre, 2D/2.5D/3D, camera projection, silhouette/detail, hand-drawn/pixel/voxel, material style, lighting, weather, atmospheric depth, animation cadence, and user-approved hero identity. Infer only what frames support; unknown game internals remain unknown.
2. Rank repositories from `references/projects.json` with `recommend`. Explain precise non-overlapping roles and licensing conditions. Prefer free and maintained repos. Never claim a particular engine generated the original reference video.
3. On "скачай следующий": keep one persistent workspace. If webgl-noise is missing, use `install-bundled` (pinned 2D/3D GLSL snapshot). If it is present and postprocessing is missing, run `extend --workspace WORKSPACE --next` or `install-bundled-postfx`: both install the verified selected upstream files for `pmndrs/postprocessing` (Zlib LICENSE + Git blob checksums) and register `postprocessing@6.39.6` as a pinned npm runtime dependency. The full library is resolved by `npm install --ignore-scripts` in the generated game; **the plugin itself contains only a partial upstream source snapshot**, not a full repository clone or npm binary. Future repos use `extend` git-cloning with HEAD hash and LICENSE verification. Never execute arbitrary upstream install scripts while fetching source. If network is unavailable, do not claim a clone or npm install happened.
4. The webgl-noise adapter injects **2D simplex noise into procedural terrain** and **3D simplex noise into animated distant cloud wisps** in two separate WebGL programs, avoiding GLSL function redefinition. Three.js is the core render dependency; the scene is still built even if optional postprocessing/physics are missing. Do not replace hero sprites, controller state, collisions or existing user art.
5. The postprocessing adapter builds a screen-layer EffectComposer with multi-resolution bloom, brightness/contrast and saturation grading, vignette, film grain and an Ashima 2D-simplex `Effect` whose screen fog coheres with the existing terrain noise. Hero identity and 3D controller remain unchanged; `P` enables/disables the screen FX without altering play state. Never mark the npm runtime installed until `npm install --ignore-scripts` succeeds.
6. Rapier physics integration (v1.3): run `install-bundled-rapier --workspace WORKSPACE` after bundled noise and postprocessing, or `extend --next`. This verifies a pinned **partial GitHub TypeScript source snapshot** and Apache-2.0 license. The full WASM physics engine is NOT included: use `@dimforge/rapier3d-compat@0.21.0` via `npm install --ignore-scripts`. On build, use `templates/physics.js` as a separate adapter: ground/pillars are collision bodies, ONE player kinematic capsule handles sliding/step/grounding, props are simulated rigid bodies and visually rendered in Three.js. No duplicate movement code when Rapier is active. Jump only on Space/touch, fallback stays playable if WASM fails. Do NOT claim full Rapier repository was cloned or the npm dependency installed by updating the skill.
7. OpenCV stage (v1.4): `install-bundled-opencv --workspace WORKSPACE` or `extend --next` after Rapier verifies a **partial upstream snapshot** at OpenCV tag 4.13.0 (Apache-2.0 LICENSE and `samples/python/opt_flow.py`, exact Git blob checksums). Python runtime is separately pinned `opencv-python-headless==4.13.0.92`; the plugin does not embed any OpenCV C++/Python binary. `analyze` on an OpenCV-enabled workspace adds deterministic Lab palette clustering and true **adjacent-frame** Farneback dense flow (up to 8 pairs, cut filtering), writes `motion_vectors.jpg` and measured optics in `style_profile.json`. Never infer character identity, depth, or camera motion from global flow alone. The generated game consumes the measured palette/detail/visual activity only to tune fog, postfx, surface detail and particle cadence; Rapier controls movement and original art remains unchanged. If the user didn't provide video, generate a conservative default atmosphere; don't claim appearance was reconstructed.
8. MiDaS stage (v1.5): run `install-bundled-midas --workspace WORKSPACE` or `extend --next` after OpenCV. Verify Git blob integrity of the pinned **partial** MiDaS source snapshot at commit 454597... with MIT license. The complete archived repository, PyTorch runtime and pretrained weights are NOT included. Never automatically download third-party weights or call raw torch.hub remote code. For actual inference the user must supply an exact pinned complete local MiDaS checkout AND weights of verified provenance, then `infer-midas --repo ... --weights ... --image ... --workspace ...`. Alternative `import-depth --image ... --depth-map ... --workspace ...` accepts a user-provided relative-depth map and never claims MiDaS ran. This saves depth/reference.png + depth/relative-depth.png and hashes; `build` creates 3 multilayer camera-facing 2.5D parallax bands. Their depth masks/offsets affect appearance only; NEVER create character obstacles, collision bodies, physics, metric measurements or animation from estimated relative depth. Three.js renders imagery, Ashima GLSL adds atmospheric haze, pmndrs/postprocessing grades the result, Rapier remains the collision authority, OpenCV maintains palette and frame motion. The repository is archived; do not call it a maintained active model. On missing depth, leave the existing scene untouched.
9. PySceneDetect stage (v1.6): after OpenCV and MiDaS, run `install-bundled-scenes --workspace WORKSPACE` or `extend --next` to add the **pinned partial** source snapshot at PySceneDetect v0.7.3 (BSD-3-Clause; full Python distribution NOT bundled). Install `scenedetect==0.7.3` explicitly before expecting the actual PySceneDetect cuts. Re-running `analyze` on a video writes `scenes/shot-NNN.jpg`, `scenes/scene_map.json`, `scene_contact_sheet.jpg`, and independent per-shot Lab palettes. `build` includes up to 12 scene presets; press N to change atmospheric color grade without changing hero physics, sprite identity, or depth collisions. `scenes_pyscenedetect.py` uses a **clearly labeled OpenCV fallback** if the PySceneDetect distribution is absent; never claim actual PySceneDetect execution in that case. Do not infer that shot cuts equal level transitions, and do not automatically run MiDaS without an approved model/weights.
10. GLB authoring + glTF-Transform stage (v1.7): use `install-bundled-gltf-transform --workspace WORKSPACE` only after pinned PySceneDetect. The source snapshot consists of `packages/functions/src/meshopt.ts` + MIT LICENSE at glTF-Transform v4.5.1 commit 41156dfa..., checked with Git blob SHA-1. It is **not** the complete repository or a globally installed CLI. Register static non-hero GLB with `import-model --workspace ... --input ... --name ...` (only authored .glb, never approved hero art). Optionally give manually authored `--collider WIDTH HEIGHT DEPTH`, a conservative Rapier box. For actual Meshopt compression run `optimize-model --workspace ... --name ...`; the command attempts to install pinned `@gltf-transform/cli@4.5.1` inside `WORKSPACE/tools/gltf-transform` with npm lifecycle hooks disabled, and fails safely if networking/npm is unavailable. This invokes the CLI in an isolated subprocess; validates the output GLB, preserved mesh/material/texture/skin/animation counts and animation names; stores SHA-256 before/after; never silently overwrites. CLI may quantize mesh positions, so visual losslessness is not guaranteed: retain original. The generated game loads optional models through Three.js GLTFLoader+MeshoptDecoder and applies only explicit box collisions in Rapier, while existing OpenCV, MiDaS, PySceneDetect, WebGL Noise, postprocessing and hero identity stay unchanged. No model? Existing scene remains unchanged. No CLI? Import still works, compression correctly unavailable.
11. **v1.8 three-mesh-bvh**: `install-bundled-mesh-bvh --workspace WORKSPACE` or `extend --next` after glTF-Transform. Verify pinned MIT snapshot v0.9.18 (`LICENSE`, `src/index.js`) against Git blob SHA-1 and record exact commit. Runtime only via pinned `three-mesh-bvh@0.9.18` npm dependency in a Vite game. `spatial.js` builds `MeshBVH` once per static, non-skinned, non-morph mesh, using `indirect:true` to preserve geometry indices; no global monkeypatching. Static pillar meshes and imported GLB scene props become accelerated visual-ray targets. `E` scans a visible geometric surface with an animated ring; camera line-of-sight uses only visual raycast and leaves collision to Rapier. No BVH bounds are silently promoted to collision bodies. Protect approved hero sprites and all movement states. If no package install possible, mark demo as unlaunched and supply accurate source only. Optional failure leaves existing game playable.
12. Use `build` to generate a single Vite + Three.js playable game project based on `style_profile.json` and acquired capabilities. `npm install` is needed once for live rendering; the generated game has controls, scene, GLSL ambient effects, mobile movement buttons and no automatic hero actions. If node modules cannot be downloaded, provide source and explain that runtime was not launched.
13. On subsequent open-source requests, preserve the same workspace and lock state; patch capabilities and regenerate from source while preserving `src/custom/` game-specific assets and art. If code is added to an already installed GPT plugin and authorized plugin-edit tools exist, publish a **new release of the SAME plugin ID** using guarded update; never create a confusing second plugin.
14. Deliver playable game link only when genuinely hosted/accessible or after checking a local file exists; do not claim that a GitHub HTML source URL is playable.

## Integration contract
- Each project has exactly one responsibility: video segmentation, visual analysis, rendering, GLSL, post-fx, physics, or relative depth.
- Ordered registration, explicit requirements, no silent replacements or upgrades, pinned Git commit SHA, and license notices are mandatory.
- `three@0.186.1` + `postprocessing@6.39.6` peer compatibility; current `dimforge/rapier` repository supersedes archived `rapier.js` repository. Check live upstream compatibility before upgrading.
- Any upstream `LICENSE` must be preserved when distributing incorporated source. Keep a third-party notice file. Third-party model weights, textures, sprites, audio, and game-specific art require independent license checks.
- Never run unknown install hooks/postinstall scripts without inspection. `extend` clones source only; dependency installation runs only on explicit build authorization.
- Never treat a video as a full scene reconstruction. Match visible appearance with authored materials, geometry, textures and lighting; point out missing viewpoints and assets. Do not infer licenses for footage.
- Visual quality gates: independently readable deep/mid/near/screen layers; exact hero identity across all actions; keyboard and touch controls; no unintended movement/actions; visible changes for new integrations; reasonable mobile FPS; graceful fallback if postprocessing or Rapier runtime fails to load.
- Output only deliverables requested by user; no unsolicited reports.

```bash
# Optional, only when @gltf-transform/cli@4.5.1 is installed locally:
python skills/game-style-forge/scripts/styleforge.py optimize-model --workspace /path/workspace --name obelisk
python skills/game-style-forge/scripts/styleforge.py import-depth --workspace /path/workspace --image /path/reference.png --depth-map /path/relative-depth.png

cd /path/game && npm install --ignore-scripts && npm run dev -- --host 0.0.0.0
```

## v1.9 three-bvh-csg: real procedural openings
On "скачай следующий" after v1.8, use `install-bundled-csg --workspace WORKSPACE`, then `build`; do not silently overwrite previously integrated modules or the approved hero. Exact upstream partial GitHub snapshot v0.0.18, commit `0ac3a84662958579d3627bbfcd6bb81746c2d699`, MIT. Runtime package `three-bvh-csg@0.0.18` is an npm dependency, not bundled in this plugin; fetching source excerpts is not a full clone.

`templates/csg.js` runs real `Evaluator.evaluate(..., SUBTRACTION)` for 3D arch / windows using watertight brushes. Result is registered with the existing `three-mesh-bvh` *only for visual queries*. Manually authored solid-part box colliders go to Rapier, leaving doorway open. The carved architecture is visible from several camera angles with continuous atmospheric glow/particles but does not alter hero identity or input. New CSG brush evaluations must be done at initialization/editor time, not on every animation frame. No CSG on deformed/skinned hero meshes, nonwatertight assets, or source GLB by default. Monitor triangle count and memory; fall back to original world when CSG fails. Real browser render checks in both portrait/landscape are required before claiming visual PASS. `animated-world-guard` continues to apply, unchanged.


## v1.10 Recast/Detour integration (required)
- On next integration after CSG, run `install-bundled-navigation --workspace PATH`. Git blob hashes and the MIT license MUST validate before registering; full library is installed later from npm. Never assert a WASM runtime was downloaded simply because source is pinned.
- Build `navigation.js` and `navigation-grid.js` with a pinned `recast-navigation@0.44.0` + `@recast-navigation/three@0.44.0` pair. Create navmesh ONLY from authored geometry (CSG walls, static pillars, explicit floor); never use relative MiDaS depth or video image pixels for walkable collision geometry.
- Route NPC agents with Recast NavMeshQuery; install corresponding kinematic NPC colliders in the existing Rapier world. If WASM generation fails, use openly labeled grid routing with the SAME authored obstacles/doorway; never claim Recast executed.
- All ambient NPCs must move on asynchronous, independent patrol loops with visible breathing, arm/head motion and lamp light modulation; hero still moves or attacks ONLY on input. Preserve their identity and previous visual style. Do not replace user-approved art.
- Preserve the fullscreen portrait/landscape and animated world guard. `npm install --ignore-scripts` is necessary in a networked game build environment; the source-only plugin does not install runtime packages.

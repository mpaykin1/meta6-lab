# Hero Animator — 3D RIG + ORIGINAL 2D ART

## Обязательный результат

Полная игра из оригинальных утверждённых GIF/PNG, с физическим 3D-миром, анимированной 2D-графикой, атмосферным GLSL и ручным управлением. Сохраняй **единственный** Hero Animator, не делай ответвлений и не подменяй исходные изображения программно нарисованными Canvas-фигурами.

Для каждой игры соблюдай `references/visual-completeness.md` и `scripts/game_readiness.py`: полноценные направления всех действий (включая grab/hurt/death), foot anchor, дистанция шага, контактная тень, альфа-края, объёмная сцена, согласованный свет, desktop/touch ввод. BLOCKED не объявлять PASS. При нехватке арта показывать кандидаты на утверждение, а не выдуманную готовую игру. Не писать отчёты, handoff или evidence без прямой просьбы.

## Независимые контракты — все обязательны

1. **Art Lock:** утверждённый RGBA pixel-exact, SHA256 originals. Любой рендеринг сохраняет оригинальную графику. `references/approved-gif-lock.md`, `references/asset-first.md`.
2. **Character Identity / Single Hero Source Lock:** один `hero_id` во всех действиях и ракурсах. Явно утверждённые отдельные клипы, SHA256 и художественная проверка. Хэш не доказывает визуальную идентичность. `references/character-identity-lock.md`, `references/single-hero-source.md`.
3. **Input Lock:** движение, прыжок, атака, уклонение, перекат, присед, захват, взаимодействие — только в ответ на настоящий ввод. Урон и смерть — только причинные игровые события. При отпускании движения герой переходит в `idle`. `references/strict-input.md`.
4. **View Lock:** 4 обязательных вида front/back/left/right, предпочтительно 8 с диагоналями. Все обязательные действия должны быть нарисованы. Никаких программных подделок недостающих ракурсов. `references/four-eight-way-3d.md`.
5. **Offline Lock:** HTML/ZIP только после настоящей сборки Three.js, Rapier WASM, PNG и JSON, запуска без CDN/CORS, не выдавать `hybrid-three.template.html` за готовую игру. `references/offline-file-safe.md`.
6. **AI Art Preparation Lock:** rembg/RIFE создают неутверждённые кандидаты в отдельных каталогах. Они не попадают в игровой атлас без визуальной приёмки и нового approval с SHA256. `references/rembg-rife.md`, `references/rife-frame-interpolation.md`.
7. **MaxRects Layout Lock (v0.11.0):** реальный upstream `maxrects-packer@3.0.0` используется **только после художественного утверждения** для компактной раскладки PNG. Он не генерирует новые изображения. Без поворотов или ресайза, исходный порядок клипов и foot pivot сохраняются, формат атласов и хэшей совместим с текущим Three.js/Rapier. Нельзя имитировать MaxRects при отсутствии npm-пакета. `references/maxrects-atlas.md`.
8. **Rapier Physics Lock:** новый 3D-мир использует **только** `@dimforge/rapier3d-compat@0.21.0` с настоящим WASM и `runtime/rapier-world.mjs` + `runtime/rapier-directional-controller.mjs`. Не запускать дополнительную AABB-физику или вторую гравитацию; коллайдеры должны соответствовать видимой геометрии. `references/rapier-3d-physics.md`.
9. **PostFX Art Lock (v0.12.0):** официальный `postprocessing@6.39.6` работает поверх того же `Three.js + Rapier` через `runtime/hero-postfx.mjs` и `runtime/hero-rapier-postfx-loop.mjs`. Воспользуйся `references/postprocessing-rapier.md`: `EffectComposer` + `SelectiveBloomEffect` только для настоящих светящихся объектов мира, НЕ для героя, world `FogExp2`, необязательная vignette только по явному согласию. Прямой renderer fallback при низком FPS, без изменения original RGBA и без второго физического update.

10. **glTF-Transform Geometry Lock (v0.13.0):** официальный `@gltf-transform/{core,extensions,functions}@4.5.1` + `meshoptimizer@1.3.0` работает **только на физической геометрии окружения GLB** во время сборки, никогда на оригинальных PNG/GIF, MaxRects-атласах или художественно утверждённых частях героя. `scripts/gltf_prepare.mjs` делает дедупликацию общих vertex-данных, опциональный Meshopt для статической сцены, извлекает `COLLIDER_*` треугольники из **исходного** GLB до квантования и записывает физические данные в `*.colliders.json`. Проверяй неизменность имён/матриц узлов, изображений текстур, alpha-материалов и анимаций. `runtime/gltf-rapier-scene.mjs` связывает Three.js GLTFLoader + MeshoptDecoder с `physics.addStaticTrimesh` в том же Rapier мире, постобработка действует только после загрузки. Любая несовместимость GLB, отсутствующий реальный исходник, несоответствующие коллайдеры или неполный офлайн-бандл — BLOCKED. `references/gltf-transform-rapier.md`.

## Единый конвейер, усиление каждого компонента

1. Исходные GIF/PNG — канонический персонаж + действие + настоящий ракурс; декодировать в lossless RGBA с единым foot pivot, по каталогам `<action>_<direction>/*.png`, не менять оригиналы.
2. Если есть фон, `scripts/rembg_frames.py` или `scripts/rembg_rife.py` создают **отдельные неутверждённые RGBA кандидаты**; прозрачноe исходное изображение не трогать. Никаких платных облачных API, ONNX веса отдельно.
3. При необходимости плавного движения `scripts/rife_frames.py` с настоящим pretrained checkpoint добавляет промежуточные кадры. RIFE нельзя запускать между разными действиями/видами, нельзя считать синтезированные кадры утверждёнными. Увеличение числа кадров не означает рост FPS игры.
4. Просмотреть каждую новую позу, лицо, одежду, контур, оружие, прозрачность, pivot. После прямого одобрения перенести в отдельный approved каталог и снять `scripts/directional_pack.py --fingerprints`. `approved:true` всегда только после художественной приёмки, не генерировать автоматически. Перепроверить события `hitStart/hitEnd` и хитбоксы, если RIFE изменил кадровую частоту.
5. **Default atlas:** `python scripts/directional_pack.py APPROVED OUTPUT --id hero --approval approved.json --directions 8 --packer maxrects --max-width 2048 --max-height 2048 --padding 2`. Пакер `images2atlas.py` теперь по умолчанию вызывает настоящую MaxRects библиотеку через `scripts/maxrects_layout.mjs`, объединяет разные анимации в общий набор листов, не меняет RGBA-байты и сохраняет `anims[].sheet` + `frames[x,y,w,h,ox,oy]` и `identity`/events JSON. Пакет `maxrects-packer@3.0.0` ставится при первом использовании в build-среде; если установки нет, не утверждать MaxRects PASS, допускается явно `--packer shelf` только для старых игр. `references/maxrects-atlas.md`.
6. **World GLB:** когда реальное окружение в `.glb`, до игровой сборки запусти `node scripts/gltf_prepare.mjs ORIGINAL.glb GAME/assets/world.glb --meshopt --require-colliders` (пакеты glTF-Transform и meshoptimizer установлены в buildtools). Отдельный `*.colliders.json` содержит Rapier-коллайдеры, построенные из **неизменной исходной** геометрии. Импортируй `runtime/gltf-rapier-scene.mjs` в игровом проекте и вызывай `loadGLBIntoRapierWorld` после инициализации `physics`, до игрового цикла; визуальная геометрия, коллайдеры и выборочный bloom остаются синхронны. Не генерируй коллайдеры из квантованного GLB и не применяй Meshopt к героям/анимированным персонажам. См. `references/gltf-transform-rapier.md`.
7. **Physics/runtime:** `runtime/hero-hybrid.mjs` отображает утверждённые PNG-атласы; `runtime/rapier-world.mjs` и `runtime/rapier-directional-controller.mjs` реализуют положение, капсулу, уклоны, столкновения, прыжки, присед/перекат и расчёт атак. Никакой Canvas-подмены героев. Для прежних игр `runtime/directional-controller.mjs` оставлен как legacy, без параллельного применения с Rapier.
8. **PostFX (основная графика):** после Rapier и обновления спрайта вызывай `runtime/hero-rapier-postfx-loop.mjs` → `runtime/hero-postfx.mjs`, НИКОГДА отдельный `renderer.render` в том же кадре. Включай `SelectiveBloomEffect` только для реальных излучающих мешей мира; `FogExp2` на материалах мира; без полной цветокоррекции или размытия авторского героя. Тени/дым/молнии/силуэты — через настоящие Three.js объекты и GLSL, а не через подмену персонажа. При FPS<30 кратковременно отключать дорогие экранные эффекты, не Rapier и не ввод. Реальный npm `postprocessing@6.39.6` + `three@0.180.0` установи в игровом проекте, `examples/rapier-3d-game.package.json`. Для нового игрового проекта выполнить `node scripts/prepare_postfx_game.mjs PATH_TO_GAME`: реальные runtime модули копируются в игровой `src/hero-animator`, npm зависимость `postprocessing` разрешается из самой игры; затем сборщик `rapier_bundle.mjs` встраивает JS + WASM и фактический арт. В новой 3D игре использовать только один RAF: Rapier → art → environmental FX → composer. Если 3D офлайн-бандлер не встраивает postprocessing, Rapier, Three.js, все атласы/JSON — не обозначать заготовку автономной игрой.
9. Игровая графика и анимации должны быть действительно видны в готовом HTML. Запуск, touch/keyboard команды и все действия проверять визуально; ссылку на игру давать только если игра реально существует и запущена.

## Управление

`W/↑`, `S/↓`, `A/←`, `D/→` — движение относительно камеры; `Shift` — бег; `Space` — прыжок; `C/Ctrl` (держать) — присед; `Q` — уклонение; `F` — перекат; `J` — атака; `G` (держать) — захват реальной цели; `E` — взаимодействие; `R` — рестарт. Мышь/свайп — камера, колесо — zoom; отдельные touch-кнопки на телефоне. Никакого действия без ввода.

## Режим 2.5D

Старые `gif2game.py` и `offline_pack.py` не удалять; управление 2D не смешивать с 3D. Новый компактный MaxRects при упаковке статичных кадров не меняет исходные RGBA-ассеты и согласуется с прежним JSON. 3D физика — невидимая структура, а не обещание полноценной 3D-модели из бокового GIF.

## Запреты

Никакого фальшивого готового URL, отсутствующих ассетов, второй копии плагина, автоматического художественного одобрения AI-кандидатов, замены героя при атаке/остановке, случайных действий, подмены MaxRects самодельным алгоритмом, ненастоящего Rapier WASM. Старые и новые функции должны усиливать друг друга в одном skill. Не использовать фальшивый PostFX или CDN, не подвергать героя глобальному bloom, blur, grade или vignette без явного художественного одобрения.


## 0.17.0 — legacy repair/playtest adapter for the supplied Ash Frontier

Для ремонта существующего `index (3).html` есть отдельный исполняемый путь, сохраняющий исходный WebGL renderer: `pack_action_grids.py` → `complete_ash_game.py ORIGINAL.html PACK.json OUTPUT.html --canonical REFERENCE.png`. Это legacy-адаптер игрового просмотра, не новый Rapier/Three.js проект, не замена основного конвейера и не заявление, что Rapier/PostFX встроены в исходный WebGL. Все новые модули 0.16.0 и дополнительные skills остаются без изменений.

`runtime/ash-adventure.js` реализует только один игровой update с настоящим вводом: здоровье/выносливость, причинный урон/смерть, атака с окном попадания по цели, удержание/освобождение/перемещение броска, E-подбор трёх печатей, портал, победа/поражение/рестарт и пауза. Стражи — объёмные каменные объекты окружения, не Canvas-подмена авторского героя. Для нового 3D проекта обязателен основной Rapier конвейер, legacy body-проверки с ним не совмещать.

В проверяемом пакете 44 клипа × 8 отдельных полнотелых кадров = 352 PNG-позы четырёх видов, без warping/RIFE персонажа. Исходные листы по 6 поз дополнены двумя отдельно нарисованными позами на действие из 4×6 supplementary grids; использовать pack_action_grids.py INPUT OUTPUT --extras EXTRA_DIR --canonical REFERENCE.png. Исходники сохраняются. Спрайт с непрозрачным/полупрозрачным белым фоном блокируется ДО нормализации: сначала штатный cut_white.py/rembg в отдельный candidate, затем повторная проверка. Не удалять такую ошибку снижением порогов. Новый regression test_grid_candidates.py подтверждает отказ на белом прямоугольнике и сохранность реального прозрачного спрайта. Metadata human_reviewed_each_frame остаётся false до фактического ответа пользователя; canonical approval не выдавать за approval всех новых кадров. Требования character_frame_gate и отдельных frame-by-frame/animated-world skills сохраняются. Игровой просмотр новых кадров — PREVIEW художественной приёмки, даже если все технические проверки и прохождение успешны.

`test_adventure.mjs` проверяет тот же held/pressed input до победы, включая реальный AI-урон, смерть, рестарт и бросок. `test_complete_builder.py PACK.json` проверяет реальный набор и отрицательные случаи: потерянный вид, внешний URL, неверный canonical SHA, выход за атлас. Сборщик встраивает изображения/JS без CDN/fetch и сохраняет исходный HTML. После сборки обязательна отдельная браузерная offline проверка keyboard/touch в desktop/portrait/landscape и реальное прохождение; structural PASS не равен художественному PASS. Новые исходники и неутверждённые кадры не включать в approved папку автоматически.

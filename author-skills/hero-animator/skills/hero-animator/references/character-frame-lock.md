# Character Frame Lock — абсолютный запрет деформации персонажей

Соблюдать `../../frame-by-frame-characters/SKILL.md` одновременно с Art Lock / Identity Lock / Input Lock / Animated World Guard.

- Никакого `cv2.remap`, `warpAffine`, `warpPerspective`, morph targets, bone-skinning, RIFE / optical flow / frame interpolation для персонажа, cat, dog, bird, NPC, enemy или игрока. Жёсткое позиционирование **целого заранее нарисованного спрайта** допускается; rotate, zoom, shear, crop-анимация, части тела, ручки/хвостики и «шевеление изображения» запрещены.
- `action/view/frame_000.png … frame_015.png`: каждая PNG — полноценное самостоятельное изображение всего персонажа с согласованными идентичностью, масштабом, foot anchor и фиксированным полотном; рисуются руками или художественной генерацией с обязательной визуальной приёмкой каждого кадра. Missing frames = BLOCKED. Самообозначение `approved:true` никогда не ставить автоматически.
- Проверять реальное действие (ноги переставлены при ходьбе, чашка перемещена в руку при питье, книга открыта при чтении, кошачьи лапы/голова имеют отдельно нарисованные позы). Не засчитывать дубли PNG, случайный jitter, простой сдвиг голого слоя или косметический свет.
- Рендерер: сменить указатель на новый существующий кадр из атласа + целочисленное перемещение по игровому миру. Ни одна операция по пиксельному warp/morph на персонаже во время рендера не разрешена. RIFE разрешён на частицах, дыме и не-actor фоновой погоде без субъектов.
- Включить `character_frame_gate.py` с обязательным просмотром кадров и визуальным худож. сравнением к оригинальному эскизу. Автоматический анализ не заменяет художественную экспертизу.
- Проектный GIF не считается финальным, если какой-либо видимый NPC остался нарисован лишь одним исходным кадром.

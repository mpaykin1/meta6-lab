# CHARACTER IDENTITY LOCK — один герой во всех действиях и ракурсах

Это абсолютный контракт, обязательный для Hero Animator.

**Герой не может меняться** при переходах idle → walk → run → crouch → jump → attack → pickup, при получении урона и смерти. Имена файлов, жанр и схожая одежда не доказывают, что GIF содержат того же героя. Самопроизвольная смена облика = блокировка игры.

## Сначала графика, потом игра

1. Утвердить единственный дизайн персонажа: пропорции, капюшон, плащ, рюкзак, обувь, оружие, текстуру, цвет, силуэт, сторону и вид камеры.
2. Все необходимые действия нарисовать **для того же героя**. Показать настоящие GIF для каждой анимации. Утверждение стиля/покоя не означает, что любой чужой attack GIF одобрен. Для каждого нового ракурса нужен согласованный художественный материал, не процедурная замена.
3. Перед сборкой просмотреть **каждый кадр** каждого action GIF в полном размере и получить одобрение изображений одного и того же персонажа. Неподтверждённые действия не допустимы. Генератор не способен объективно доказать идентичность художественного героя по SHA256; SHA256 обеспечивает лишь сохранность одобренных конкретных кадров.
4. Зафиксировать `character_lock`: `hero_id`, `approved: true`, SHA256 одного эталонного GIF и отдельные SHA256 и индексы кадров **для каждого действия**. Запрет на автоматическое смешивание GIF персонажей, даже если похожи.
5. Генератор проверяет строгую связь action→одобренный asset, а runtime читает только согласованный action-list. Нет анимации — нет действия; если действие нужно по заданию — блокировать готовность сборки, а не подменять другим GIF.

## Пример roles.json

SHA256 в примере — текстовый маркер: в реальной сборке использовать 64 hex-символа, вычисленные с **фактических** исходных GIF. Не использовать примерные значения.

```json
{
  "roles": {"background":"ruins.gif", "portal":"portal.gif", "extras":[]},
  "character_lock": {
    "hero_id":"ash-wanderer",
    "approved":true,
    "reference_sha256":"<sha256 of approved idle.gif>",
    "required_actions":["idle","walk","run","crouch","jump","attack","pickup"],
    "actions":{
      "idle":{"sha256":"<sha256 of approved idle.gif>","frames":[0]},
      "walk":{"sha256":"<sha256 of approved walk.gif>","frames":[0,1,2,3]},
      "run":{"sha256":"<sha256 of approved run.gif>","frames":[0,1,2,3]},
      "crouch":{"sha256":"<sha256 of approved crouch.gif>","frames":[0]},
      "jump":{"sha256":"<sha256 of approved jump.gif>","frames":[0,1,2,3]},
      "attack":{"sha256":"<sha256 of approved attack.gif>","frames":[0,1,2,3]},
      "pickup":{"sha256":"<sha256 of approved pickup.gif>","frames":[0,1,2,3]}
    }
  }
}
```

Поля `roles` должны содержать только сценические роли или совпадать с `character_lock`; для actions можно вообще не указывать поля `roles`, они устанавливаются автоматически из пакета. `segments` должны совпадать с approved `frames`, если указаны. Генератор проверяет, что каждый SHA256 соответствует входному GIF. Для нескольких ракурсов — отдельный именованный набор `hero_id` с одобрением для каждого направления.

### Технический предел

Сравнение SHA256 и привязка `hero_id` не доказывают визуальной идентичности **разных GIF**; от чужой графики защищают обязательная покадровая проверка и явное одобрение. Не обещай 100% автоматического распознавания. Утверждённые GIF сохраняются lossless и не перерисовываются.

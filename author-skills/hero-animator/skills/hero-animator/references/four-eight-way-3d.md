# Painterly 3D — обязательная технология направленных рисованных героев

**Единственный активный 3D-подход в Hero Animator:** объёмный невидимый персонаж + художественный многовидовой спрайт + настоящая 3D-геометрия мира. Пользователь приносит GIF/PNG и эскизы; никакой подмены изображений примитивами.

## Как добиться объёма, не потеряв стиль

- **Настоящий 3D-мир**: земля с высотами, маски глубины, поверхности руин, препятствия, коллайдеры. Из исходных авторских слоёв: дальний план, стволы, стены, дым, огонь, передний план на разных `z` и `y`, взаимодействие с глубиной через depthTest. Нет необходимости строить видимую пластмассовую модель поверх рисунка.
- **Герой**: 3D-корень, капсула/Box3 и якоря ступней/рук/оружия; персонаж выглядит как RGBA-анимация на ориентированной к камере плоскости. Это *не одна боковая GIF*, она обязательна в 4 ракурсах.
- **4 необходимых ракурса**: `front` (лицом к камере), `back` (спиной), `left`, `right`. В 3D по умолчанию **8 видов** (диагонали `front_left`, `front_right`, `back_left`, `back_right`) для плавной орбиты. Плоскость смотрит на камеру, её текстура выбирается по относительному углу *модели к камере*, с гистерезисом, чтобы не дрожала на границе.
- **Не поворачивать боковую GIF как 3D-объект**: с торца персонаж станет бумажной полоской; нельзя показывать вид спереди/сзади с боковой графикой. Не создавать зеркальную копию асимметричного персонажа вместо правого/левого ракурса. Нельзя считать автоматический псевдо-3D вид подтверждённым художественным оригиналом.
- **Стабильная личность**: единый `hero_id`, канонический лист модели в 8 ракурсах, одни и те же капюшон, плащ, сумка, застёжка, руки, обувь, оружие, цвет фактуры. Масштаб, положение стоп, размеры персонажа, источники света и линия горизонта согласованы между анимациями. Все кадровые источники визуально просмотреть и получить одобрение. Контроль SHA256 проверяет неизменность данных, но **не гарантирует внешнее сходство**.
- **Для ещё большего 3D**: отдельно нарисованные спрайты тела/плаща/рук могут быть посажены на настоящие кости, с depth mask и тенью на геометрии пола. Делать только при доступных отдельных авторских частях; не разрезать без одобрения. Задний план получает parallax и атмосферную перспективу, экран — тонкие GLSL haze, embers, heat, не заменяющие краску.

## Матрица графики — сборка блокируется при пропусках

```
hero_id/<action>_<view>/<frame number>.png
idle_front, idle_right, idle_back, idle_left
walk_front, walk_right, walk_back, walk_left
run_front, run_right, run_back, run_left
jump_front, jump_right, jump_back, jump_left
crouch_front, crouch_right, crouch_back, crouch_left
dodge_front, dodge_right, dodge_back, dodge_left
roll_front, roll_right, roll_back, roll_left
attack_front, attack_right, attack_back, attack_left
```

Для 8-направленного режима у **каждого** действия добавь `front_right`, `back_right`, `back_left`, `front_left`. Итого: 8 действий × 8 ракурсов = 64 разных анимационных клипа. Кадры атласа могут быть многочисленными, но никакой ракурс не может быть выдуман из бокового клипа. Если текущий пользователь предоставил только `left/right` GIF, сначала дорисуй `front/back` в ТОЧНО том же утверждённом облике и покажи пользователю на одобрение; 3D 360° до этого не выпускай.

## Рабочий pipeline внутри того же плагина

1. Исходные GIF → декодирование в RGBA PNG **без изменений рисунка**; каждый клип в отдельную папку `action_direction`, один фиксированный canvas и одна нижняя точка опоры в мировом масштабе.
2. Канонический reference character sheet 4/8 видов → визуальная проверка характерных деталей, затем explicit approval manifest `hero_id`, `approved`, `reference_sha256`, `actions` fingerprint на **каждый** ракурс/действие.
3. Скрипт `scripts/directional_pack.py`: сначала `--fingerprints` для снятия хэшей **без фиктивного approval**, после явного одобрения `--approval approved.json --directions 8`. Он проверяет все клипы, запускает существующий `images2atlas.py` и дописывает `identity`, `source_sha256` и `directional` в JSON. В игровой папке должны быть реально существующие PNG-атласы, а не ссылки на исходные местоположения пользователя.
4. Используй `loadHybridActor` из `runtime/hero-hybrid.mjs`, затем `createDirectionalController` из `runtime/directional-controller.mjs`: этот контроллер принудительно запрещает подмену текущего вида другой анимацией и подбирает нужный кадр по положению 3D-камеры. Перед созданием обязательно `validateDirectionalHero(meta,{directions:8})` — иначе выпуск запрещён.
5. Земля должна определять `floorAt(x,z)`; камера следует за героем, движется вокруг него, игровое состояние обновляет 3D-корень, отрисовка hero._frame следует из состояния. Ступни стоят на земле, прыжок использует настоящую y-физику, перекат двигает root, а не телепортирует сам спрайт.
6. Если нужен прямой запуск двойным кликом из Windows, собрать standalone `index.html` с вшитыми JSON, runtime, оригинальными PNG/WebP и движком как в `offline-file-safe.md`. Отдельная `module` + `fetch(local)` **не финальный продукт**. Требования автономности остаются обязательными и при новом 8-way режиме. Если текущий офлайн-упаковщик не умеет новую 3D-матрицу — расширить его, а не выдавать несовместимый HTML.

## Подключение runtime (для сборщика, не готовая самодостаточная игра)

```js
import {loadHybridActor} from './runtime/hero-hybrid.mjs';
import {createDirectionalController,validateDirectionalHero} from './runtime/directional-controller.mjs';
const meta=await loadApprovedAtlasMetadata(); // actual inline/hosted data, NOT an unspecified function in shipped game
validateDirectionalHero(meta,{directions:8});
const actor=await loadHybridActor({THREE,atlasUrl:atlasUrlFromActualBundle,
  worldHeight:1.8,billboard:true,multiAngle:true,wobble:0.002});
scene.add(actor.root);
const controller=createDirectionalController({THREE,actor,camera,canvas:renderer.domElement,
  directions:8,floorAt:(x,z)=>sampleRealCollisionTerrain(x,z),blocks:realStaticColliderBoxes,
  onAttack:({hitbox})=>applyCombatOnce(hitbox),onInteract:()=>interactIfInRange()});
function tick(){const dt=Math.min(clock.getDelta(),.05);controller.update(dt);renderer.render(scene,camera);requestAnimationFrame(tick);}
tick();
```

В реальном выпускаемом коде функции `loadApprovedAtlasMetadata`, `sampleRealCollisionTerrain`, `applyCombatOnce`, `interactIfInRange` и константы — **действительные реализации на основе игрового проекта**, а не оставленные заглушки. Добавляй указанные импорты в bundle при сборке, без неопределённых символов.

## Управление, 3D-режим (отличается от старой боковой 2D-игры)

- `W/A/S/D`, стрелки — вперёд / влево / назад / вправо **относительно камеры**, без автодвижения. `S/↓` означает шаг к камере, благодаря чему виден **front**; `W/↑` вдаль от камеры — **back**. A/D выбирают боковые ракурсы. По диагонали — 8 направлений.
- `Shift` + движение — бег; `Space` — одиночный прыжок по нажатию и только с земли; `C` или `Ctrl` — приседать пока удерживается, прекращать по отпусканию.
- `Q` — разовое уклонение, `F` — разовый перекат по земле, `J` — одна атака на одно нажатие с утверждёнными ударными кадрами; `E` — только ручное взаимодействие в пределах досягаемости; `R` — ручной рестарт, если игра его предоставляет.
- Мышью/пальцем по пустому полю — поворот камеры вокруг героя до 360°, колесо — приближение. На мобильном обязательны отдельные экранные кнопки `[data-hero-key]="forward|backward|left|right|jump|crouch|dodge|roll|attack|interact|sprint"` с корректным отпусканием/pointercancel.
- Никогда не переводить персонажа в `crouch/dodge/roll/jump/attack` по таймеру, случайному проигрыванию GIF или смене направления камеры. Смена ракурса изменяет только **какую** анимацию текущего состояния показывать; она не запускает **новое** действие.

## Хитбоксы, темп и выразительность

- Сохранить один высотный масштаб, shadow decal под стопами; во время прыжка спрайт поднимается вместе с world root, тень остаётся на земле. Во время приседания тело-коллайдер ниже, анимация синхронизирована с позой. Атака имеет `hitStart/hitEnd/hitboxes`, один удар в одно окно.
- При перекате низкая капсула движется на ограниченную дистанцию с независимой от кадров скоростью; анимационный клип один раз проигрывается и завершается. Уклонение аналогично, но короче. Столкновения не отключать бесконтрольно.
- Прямо поверх авторского цвета допускается малый шейдерный shimmer/дым, но не redraw. Смену изображения между разными ракурсами не маскировать crossfade двух разных лиц: только ближайший подтверждённый ракурс с гистерезисом.

## Блокирующие случаи

- Нет `walk_front` или `walk_back` — не заявлять полноценную 3D-свободу; не запускать боковую GIF вместо этих ракурсов.
- Нет `attack_*`, `jump_*`, `roll_*`, `crouch_*`, `dodge_*` для всех требуемых видов — нужное действие не считается готовым; запросить/нарисовать новые ассеты, но не делать ложное управление.
- Нет SHA256 или ассеты визуально из разных персонажей — Character Identity Lock FAIL.
- Работает только HTTP/CDN, но ссылка обозначена как standalone — Offline Launch Lock FAIL.
- Любые самостоятельные действия героя — Input Lock FAIL.

Это **обновление того же Hero Animator**, отдельный плагин не создавать. На исходном side-only GIF один только код не может честно восстановить графику лица и спины.

# Hero Animator + MaxRects Packer: единый оптимизированный atlas pipeline

Исходник: https://github.com/soimy/maxrects-packer (MIT, Shen Yiming), зависимость **maxrects-packer@3.0.0** строго закреплена в `skills/hero-animator/package.json`. Реальный `MaxRectsPacker` вызывается из `scripts/maxrects_layout.mjs` на этапе подготовки арта, не при запуске игры. Библиотека устанавливается `npm` автоматически при первой упаковке (или один раз `npm install --ignore-scripts` в корне skill). Никаких CDN или сетевых вызовов в браузере.

## Архитектура и интеграция

`утверждённые GIF/PNG → опционально rembg (кандидат) → опционально RIFE (кандидат) → художественное утверждение каждой анимации и ракурса + SHA256 → directional_pack.py → MaxRects Packer → общие PNG-атласы + обычный JSON → HybridActor/Three.js/GLSL + Rapier WASM.`

Никакой пункт до явного художественного утверждения нельзя считать игровым ассетом. `MaxRects` **только раскладывает** RGBA-фрагменты в PNG, не меняет позы, не дорисовывает ничего, не зеркалит, не поворачивает кадры, не затрагивает `hero_id`, анимационные фазы, события атаки и хитбоксы. Это дополняет RIFE: больше кадров — плотнее укладываются, но общий размер может увеличиться. Rapier остаётся единственной 3D-физикой; MaxRects не меняет коллайдеры.

### Две стадии реальной MaxRects-упаковки

1. `MaxRectsPacker(maxWidth,maxHeight,2,{smart:true,pot:false,square:false,allowRotation:false})` размещает фрагменты **одного клипа** в собственной компактной прямоугольной области.
2. Тот же packer упаковывает компактные области разных клипов в общие PNG-атласы (например, `hero_sheet_000.png`). Один `action_direction` всегда находится в одном листе: это принципиально сохраняет старый контракт `anims[action].sheet` и `frames:[x,y,w,h,ox,oy]` без необходимости переписывать Three.js/WebGL-шейдеры, обработчики событий, 4/8 направлений или Rapier.

Кадры сохраняют порядок и исходный foot pivot, `padding >= 2`, `rot=false`, а ещё неиспользуемые прозрачные байты не перерисовываются: crop по объединению границ всех RGBA-каналов, затем прямой `paste` без альфа-композитинга и фильтрации. Потеря точных RGBA-данных, пересечение прямоугольников, выход за границы листа или невозможность разместить целый клип — **BLOCKED**. Алгоритм эвристический, не обещает математически минимальный размер; лист может отличаться от исходной версии и между версиями библиотеки.

### Основная сборка (без отдельного конвейера)

```bash
python scripts/directional_pack.py APPROVED_ART OUTPUT --id hero \
  --approval approved.json --directions 8 --packer maxrects \
  --max-width 2048 --max-height 2048 --padding 2
```

Сначала `--fingerprints` для проверки утверждённых кадров, но это **не автоматическое одобрение**. Никакой повторной проверки художественного сходства не заменяет SHA256. При первом вызове Python поставит закреплённую npm-зависимость (нужны Node.js 18+, npm и интернет для первого скачивания). Если скачивание невозможно, MAXRECTS не имитировать и не объявлять включённым; старая упаковка доступна только через явный `--packer shelf` для прежних проектов. Объёмные веса rembg/RIFE и Rapier WASM сюда не входят, это отдельные зависимости.

Предел текстур в 2048×2048 по умолчанию выбран для мобильных GPU. Допустим `--max-width 4096 --max-height 4096` только если целевой WebGL/WebGL2 поддерживает размер. Для слишком длинного клипа пакер завершится ошибкой вместо скрытого разбиения одного действия между листами, что сломало бы текущий runtime. Уменьшение размера исходников, разделение анимации на отдельные игровые действия и проверка GPU-бюджета выполняются на этапе game authoring, не за счёт замены оригинальной графики.

## Совместимость и честные ограничения

- Existing `images2atlas.py` и `directional_pack.py` теперь используют MaxRects по умолчанию; исходный legacy-режим поддерживается флагом `--packer shelf`.
- JSON содержит те же `anims[].sheet`, `anims[].frames`, `fps`, `loop`, `hold`, `release`, `hitStart`, `hitEnd`, `hitboxes` и identity hashes; новые `atlasPacker` metadata ничего не меняют в runtime.
- При новом результате возможно **меньше PNG-файлов и пустых пикселей**, но это не является гарантией роста FPS. Один герой всё равно рисуется тем же числом спрайтовых объектов; размер ZIP, скорость загрузки и потребление VRAM зависят от реальных кадров и компрессии PNG.
- Веб-игра не требует Node/npm; она читает только готовые изображения/JSON. Для действительно автономного 3D HTML по-прежнему нужен рабочий offline bundler для Three.js + Rapier + изображений. Пакер не решает этот отдельный вопрос.

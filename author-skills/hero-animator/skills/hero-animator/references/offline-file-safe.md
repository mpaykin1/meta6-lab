# OFFLINE FILE SAFE — независимый запуск на Windows

## Симптом

При открытии `C:\Users\...\Downloads\game\index.html` в Chrome показывается заставка и никакой графики. Основная причина: ES-module src="./engine.js" и fetch('./assets/game.json') недоступны из origin `file://` из-за browser CORS/security restrictions. Другой возможный фактор — отключённый CDN.

## Исправление по умолчанию

1. Используй существующий `gif2game.py` для сохранения оригинальной графики и strict input FSM. Это временный build, не финальный.
2. **Обязательно** выполни `python scripts/offline_pack.py /полный/путь/к/игре`.
3. `offline_pack.py` кладёт JSON-манифест, pixel-checked lossless WebP/PNG и JavaScript runtime внутрь одного `index.html`. Нескольких файлов больше не нужно.
4. Тот же HTML сначала пытается загрузить Three.js 0.160.1 через HTTPS в течение 1.8 секунд. При ошибке/таймауте — native WebGL2/GLSL backend; если браузер запретил WebGL — Canvas2D backend. Оба резервных пути используют те же оригинальные кадры, точные сегменты и пользовательский ввод.
5. Загрузка скрывается только после готовности текстур и движка. Ошибка отображается текстом на экране, а не вечным "ЗАГРУЗКА...".
6. Если пользователь просит полный офлайн, кода/данных извне игре не нужно. Не нужен `python -m http.server`, npm, install, localhost или GitHub Pages для локальной игры.
7. При формировании ZIP финальным источником является этот единственный HTML. Прежние `engine.js` и `assets/` не следует оставлять рядом только ради загрузки, чтобы не дублировать объём.

## Строгое управление

Используй **те же** action segments, что записаны `gif2game.py`. В покое заморожен выбранный frame 0 (или явно назначенный idle segment). `Space` — **прыжок**, `J` — **атака**, `ArrowDown` — **приседание**, `E` — ручной переход. Фоновые GIF могут анимироваться самостоятельно, персонаж — никогда.

## Приоритет

В новом скачиваемом артефакте отсутствуют локальный src="./engine.js" и fetch JSON. Любые старые примеры `file://`-несовместимой сборки не являются корректными результатами. Не утверждай, что прямой запуск через `file://` проверен, если сама тестовая среда блокирует локальную навигацию.

# STRICT INPUT LOCK — обязательная игровая механика Hero Animator

## Главный запрет

**Никаких действий игрового героя без явной команды пользователя**. Запрещены автоматические приседания, бег, перемещение, атаки, прыжки, взятие предметов, вход в портал, победы, смена оружия, переходы к незаказанным действиям. Автоплей допустим для НЕинтерактивного фона, огня, портала, пыли и тумана. Дыхание/малые idle-эффекты допустимы лишь в отдельных специально подтверждённых `idle`-кадрах, но в строгом режиме default — **единственный статичный одобренный кадр**.

### Причина критической ошибки

Один художественный GIF может содержать одновременно `idle → walk → run → crouch → idle`. Его проигрывание прямо в `<img>` или Three.js как непрерывного loop заставляет героя приседать без ввода. **Обычный GIF НЕ подходит для прямого autoplay игрока**. Разверни RGB/RGBA кадры в атлас без изменений пикселей, затем включай только кадры запрошенного действия через явную FSM.

### Обязательная карта команд (ПК)

- **Нет клавиш / потеря фокуса / скрытая вкладка** → `idle` (поза 0, frame locked, скорость 0, никакого нового action).
- **← / A** → идти влево; **→ / D** → идти вправо. При отпускании движение останавливается, возвращается `idle`. Нет auto-walk.
- **Shift + ←/→** → бег, только пока обе клавиши зажаты; отпускание Shift = ходьба, отпускание стрелки = idle. Shift сам по себе ничего не делает.
- **↑ / W / Space** → **прыжок по фронту нажатия**, только при `grounded`, без авто-прыжков при удержании, с гравитацией и приземлением. `ArrowUp` никогда не должен означать атаку.
- **↓ / S** → приседание **только при удержании** на земле, остановка горизонтального перемещения. Отпускание = idle (или шаг, если удерживается горизонтальная стрелка). Если нет одобренного кадра crouch, нельзя имитировать приседание другой анимацией; сообщить о недостающем GIF/кадре.
- **J** → атака **только по фронту нажатия**; один удар на одно нажатие, без авто-комбо, hitbox активен только во временном окне самой атаки. Возврат к idle/движению после полного клипа. Клавиша Space = прыжок, не атака.
- **E** → взятие предмета, активация портала или взаимодействие **только при нажатии и только в радиусе конкретного предмета/триггера**; никакого автоматического подбора при приближении.
- **R** → сброс только по отдельной команде (или кнопке), не auto-restart.

### Телефон

Экранные кнопки обязаны посылать **те же действия** и поддерживать `pointerdown`, `pointerup`, `pointercancel`, `lostpointercapture`, без залипающих кнопок. Кнопка вправо не должна включать прыжок/атаку. Отдельные клавиши ↕, ⚔, E. После ухода приложения в фон все нажатия сбрасываются.

### Fail-closed для смешанных GIF

Перед сборкой ОБЯЗАТЕЛЬНО смотреть **все кадры** каждого GIF игрока. Если GIF содержит несколько действий, заполнять `roles.json -> segments` со списками **точных индексов исходных кадров**, например:

```json
{
  "roles": {
    "background":"ruins.gif",
    "portal":"portal.gif",
    "idle":"hero_mixed.gif",
    "walk":"hero_mixed.gif",
    "run":"hero_mixed.gif",
    "crouch":"hero_mixed.gif",
    "attack":"attack.gif",
    "extras":[]
  },
  "segments": {
    "idle":{"clip":"hero_mixed.gif","frames":[0]},
    "walk":{"clip":"hero_mixed.gif","frames":[1,2]},
    "run":{"clip":"hero_mixed.gif","frames":[3,4,5]},
    "crouch":{"clip":"hero_mixed.gif","frames":[7]}
  }
}
```

Если семантика кадров неизвестна, **не угадывать**: назначить безопасный статичный idle, не проигрывать сомнительные фазы автоматически. При недостатке утверждённой графики для действия не подменять его чужим рисунком. Если пользователь одобрил новый GIF, тогда добавить соответствующий action clip.

### Реализация и инварианты

- `scripts/gif2game.py` строит lossless атлас с идентичными RGBA и принимает `--roles` с `segments`.
- `runtime/gif2game_engine.js`: `keydown/keyup` по `KeyboardEvent.code`; `preventDefault` на стрелках и пробеле; один input controller для ПК и мобильных кнопок.
- FSM `idle | walk | run | crouch | jump | attack | pickup`. Только событие ввода даёт право войти в actionable state. `attack` не зацикливается и не запускается повторно без нового нажатия.
- Для сцены допустимы самостоятельные атмосферные циклы; **герой** — только command-gated.
- Сравнение игрового состояния с input держать как жёсткий invariant: если в момент `no input` герой `runs/crouches/jumps/attacks/picks`, выпуск блокируется. Один статичный кадр в `idle` даже в GIF из смешанных фаз.
- Никакая оптимизация FPS или веса не может восстановить прямой GIF-autoplay для героя.

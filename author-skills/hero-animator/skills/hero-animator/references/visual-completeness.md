# Обязательное качество каждой новой игры и обновления

Это критерии выпуска, а не обещание автоматически восстановить рисунок из одного GIF. Применять ко всем создаваемым играм, включая legacy 2.5D. В боковой игре разрешены только реальные профильные направления, явно выбранные пользователем; в 3D минимум 4, по умолчанию 8. Для сохранения старого проекта можно выдать отдельно обозначенный технический preview с перечнем незавершённого арта, но не называть его полной версией.

## Порядок исполнения

1. Сохранить исходник и хеши. Снять baseline в браузере с file:// и отключённой сетью. Инвентаризировать реальные кадры; не путать переключение плоскости и нарисованный новый ракурс.
2. Проверить матрицу `idle/walk/run/jump/crouch/dodge/roll/attack/grab/hurt/death` × front/back/left/right (+ диагонали). Захват требует цель, дистанцию, проверку препятствия, удержание/освобождение и собственный клип. Удар требует цель, хитбокс, активное окно и реакцию. Не переименовывать walk в attack или grab. Если конкретная игра не имеет боя, профиль без боевых действий требует явного выбора пользователя; не исключать их молча ради PASS.
3. Недостающий арт создавать по исходному герою через доступный генератор изображений, готовить лист ракурсов и кадры. Сохранить кандидаты отдельно; показать пользователю до внесения в утверждённый runtime. Автоматический тест не даёт художественного одобрения. Если генератор недоступен или кандидат не одобрен, продолжать независимые технические исправления и честно оставить art gate BLOCKED. Не генерировать approved:true самостоятельно.
4. Сохранять единый масштаб и foot pivot. Переход действия начинает его таймлайн с нуля, смена ракурса сохраняет фазу. Не смешивать два разных лица через crossfade. Ходьба/бег синхронизированы с ФАКТИЧЕСКИМ пройденным расстоянием после столкновений; упор в стену останавливает шаги. Idle не перебирает walk. Прыжок: старт, полёт, приземление; одиночные действия не зациклены. Получение урона вызывается реальным попаданием, смерть — исчерпанием здоровья; это не нарушение ручного ввода.
5. Мягкая контактная тень остаётся на земле при прыжке, расширяется и ослабевает с высотой. Не приклеивать тень к поднятому спрайту. На рельефе следовать поверхности, не висеть над ней. Не запекать тень в исходные RGBA кадры.
6. Устранить швы атласа (half texel inset/gutters), проверить альфа-края на светлом/тёмном фоне; не стирать исходные полупрозрачные детали. Для земли использовать декоррелированные масштабы/повороты текстуры и низкочастотную вариацию, без заметной сетки. Предпочитать lossless PNG/WebP, не объявлять upscale восстановлением утраченной GIF-палитры.
7. Объёмные препятствия и передний план должны правильно перекрывать персонажа: depth test, сортировка прозрачного по глубине камеры; пустые пиксели плоскости не закрывают мир. Не сортировать только по мировому Z при вращении камеры. Не увеличивать дальний фон поверх героя. В renderer применять отдельный alpha cutout/depth pass или документированную корректную сортировку без непрозрачных прямоугольников.
8. Единая палитра/экспозиция, слабое отражённое свечение портала/огня; свет не перекрашивает оригинал в другой стиль. Источники света не пульсируют на всём мире одинаково. Сохранить layered parallax; камера не может показать несуществующую обратную сторону плоского окружения — для 360° сначала построить окружение вокруг героя, иначе ограничить и честно обозначить камеру.
9. Ввод по KeyboardEvent.code для русской/латинской раскладки; pointer capture, release/cancel/lostcapture/blur, независимые пальцы. Touch-кнопки доступны и в широком landscape через `(pointer:coarse)`. Релиз клавиши/упор в стену прекращает движение; прыжок доступен после каждого приземления; E доступна на телефоне. Ограничить dt, фоновые вкладки сбрасывают ввод.
10. Проверить desktop и portrait/landscape touch, движение/стену/отпускание, повторный jump, все направления и действия, камеру и перекрытия, WebGL ошибки, offline. Сохранить скриншоты и machine-readable evidence. Структурные проверки, browser runtime и художественную проверку учитывать отдельно.

## Инструменты в пакете

- `runtime/visual-quality.js`: общие функции matrixReport/selectView, шаг по реальному расстоянию, контактная тень, ввод без залипания. Renderer adapters обязаны реально их вызывать.
- `scripts/game_readiness.py PROJECT.json --output readiness.json`: строгий предрелизный gate. Не создавать фиктивные записи evidence; путь и SHA256 каждого подтверждения фиксируются. Отсутствующие клипы/проверки означают BLOCKED, никогда частичный PASS.
- `scripts/upgrade_ash_game.py INPUT.html OUTPUT.html`: проверяемый адаптер исходной игры «Пепельный предел» (точное распознавание исходника, сохранение встроенного арта). Он выпускает технический preview: тень, земля, освещение, корректные UV/перекрытия, шаг по расстоянию, ввод. НЕ генерирует ракурсы, бой, захват и не снимает art gate. Для других проектов адаптировать renderer, а не запускать этот патчер вслепую.
- `scripts/directional_pack.py --events events.json` переносит реальные release/hitStart/hitEnd/hitboxes в атласы. По умолчанию полный профиль; `--profile legacy` только для явной совместимости старого проекта. Проверять фактические окна попадания и освобождать захваченные цели при рестарте/смерти.

## Условия честной выдачи

Отдать проверенный HTML/ZIP, назвать реально сделанные изменения. Указать оставшийся art gate и показать конкретный кандидат для одобрения. Ссылка на опубликованный плагин подтверждает сохранение исходников, а не успех всех игр. Применение скилла — запуск его инструментов на файле пользователя и реальные проверки результата, а не новый текст рекомендаций.

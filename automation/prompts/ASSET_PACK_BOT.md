# Промпт «АССЕТ-ПАК» — универсальный, многоразовый, саморазвивающийся (Claude, 11.11.2026, v2)

Владелец вставляет текст из блока ниже в чат ChatGPT без изменений — сколько угодно раз (после зависания, в новый чат, на следующий день). Подходит для любых ассетов: 2D-спрайты, скины, 3D-модели, звук и музыка, картинки, смешанные паки и новые виды. Если владелец прикладывает ZIP или файлы — это новый пак.

```
АССЕТ-ПАК для МГ и МГЛ — любые ассеты (2D, скины, 3D, звук, музыка, картинки, смешанные и новые виды). Репозиторий mpaykin1/meta6-lab (у тебя полный доступ). Промпт многоразовый: его присылают снова без изменений — продолжай с несделанного.

0. ПРОЧИТАЙ ПЕРЕД РАБОТОЙ (из main):

   Без строки в ZADACHI.md не начинать: добавь «АССЕТ-ПАК: <имя пака>» (без дублей), статус «взято».

1. ПАК.
   - Приложен ZIP или файлы: положи как есть в asset-packs/incoming/<имя-пака>/ (ветка lab/asset-pack-<имя>), отдельным коммитом «исходник как есть».
   - Ничего не приложено: возьми пак со статусом «в работе» из PROGRESS.md; нет таких — первый пак в asset-packs/incoming/.

2. ПРОВЕРКА БОТОМ (он сам узнаёт вид пака):
   python -I automation/asset-check/check_pack.py asset-packs/incoming/<имя> --out asset-packs/incoming/<имя>/_check
   Прочитай _check/REPORT.md. Каждая строка HARD — это работа, а не отчёт.
   - U1 «вид не распознан» или C6 «файлы не проверил ни один вид» → сначала шаг 5б (научи бота этому виду), потом исправляй пак.

3. ИСПРАВЛЕНИЕ (нашёл ошибку → сам исправь, только потом отчитывайся). Иди по HARD группами, после каждой группы перезапускай бота. Как чинить по видам:
   - 2D-спрайты: перерисуй генерацией изображений, режь строго по сетке frame_size, якорь — ноги, альфа 0/255, цвета из palette. Анимации живые: в каждом кадре меняется поза (руки, ноги, корпус, голова), волна по телу с задержкой — не сдвиг и не мигание искры. Тайлы и фоны бесшовные; у каждого мира свой вид. Нужны hitbox и кадр удара.
   - Скины: по rules/01-stil-i-grafika/SKINY.md (ID KS1–KS12 = S1–S12).
   - 3D: glTF 2.0 .glb, единица = метр, низ модели на y=0, ≤ 20 000 треугольников (или LOD), текстуры ≤ 1024 и степень двойки, нормали, у скелета — анимации idle/движение/атака/урон/гибель.
   - Звук (правило ЗВУК): без перегруза, без режущих высоких (срезать верха выше 5 кГц), без тишины в начале, громкость эффектов ровная, музыка ≥ 60 с с развитием, петли без щелчка, ogg вместо тяжёлого wav; диссонансные звуки вдвое тише гармоничных.
   - Любой пак: в манифест (pack.json, если другого нет) — license, provenance, content_flags. Реальные узнаваемые люди или бренды → вторая версия пака с вымышленными героями в asset-packs/incoming/<имя>-fiction/.
   - НЕ менять то, что бот признал хорошим. Исправленный файл заменяет старый в том же пути, версия пака растёт.
   - После каждой группы: коммит файлов + _check/, обнови PROGRESS.md (пак, вид, группа, HARD было → стало, SHA). Это защита от зависания.
   - 0 HARD и зелёный прогон ASSET CHECK → перенеси пак в asset-packs/ready/<имя>/.

4. PR: один PR на пак в main meta6-lab. В описании: вид пака, HARD было → стало, ссылка на прогон ASSET CHECK, SHA. Каждое утверждение («исправлено», «зелёный», «слито») — со ссылкой, SHA или номером прогона; без доказательства не принимается. Сливай сам только при всех зелёных проверках. Если PR меняет .github/workflows — не сливай, строка в DLYA_CLAUDE.md (охранник пускает только Claude).

5. САМОРАЗВИТИЕ БОТА (каждый запуск; «делать нечего» запрещено):
   а) Посмотри на пак глазами игрока (картинки ×3 nearest, 3D — превью с трёх сторон, звук — спектр и громкость). Нашёл дефект, который бот пропустил → проверка в automation/asset-check/kinds/<вид>.py + ловушка в test_kinds.py или test_check_pack.py (маленький синтетический образец с этой ошибкой) + строка в MUTANTS в mutate_bot.py + строка в OSHIBKI.md.
   б) Новый вид ассетов (U1/C6: шрифты, шейдеры, видео, .vox, Lottie, частицы, карты уровней…) → новый файл kinds/<вид>.py по шаблону из SPEC.md («Как бот растёт до любых ассетов»): NAME, ORDER, detect, check. Есть готовый валидатор в репозитории — вызывай его, не переписывай (REUSE). Ловушки: чистый образец проходит, каждая ошибка ловится. Добавь вид в таблицу SPEC.md.
```

# МНОГОРАЗОВАЯ ЗАДАЧА: ЭТАЛОНЫ В БИБЛИОТЕКУ

Репозиторий: mpaykin1/meta6-lab (МГЛ). Промпт повторяется без изменений. Каждый запуск читает прогресс, продолжает с первой незакрытой пары «игра × шаг» и сохраняет как минимум одно проверяемое улучшение. «Делать нечего» — недопустимый исход.

## Цель

Каждая подтверждённая игра владельца — машинный эталон для чужих ИИ через MCP, не человеческая витрина: оригинал байт в байт, полная опись ассетов, отдельно исполнимые оригинальные системы со всеми зависимостями, проверка происхождения и прав, доступ через MCP. Успех — реальный Chromium, непустой canvas, реакция на ввод, реальные MCP-вызовы; наличие файла не равно PASS.

## Обязательный вход — каждый запуск

1. Прочитать automation/biblioteka/PROGRESS.md. Если файла нет — создать. Каждая пара «игра × шаг» хранит дату UTC, ссылку на PR, исходный Git blob SHA, commit SHA, Actions run ID и фактический статус. Готовую пару пропустить; при изменении Git blob исходника открыть её заново. Записывать прогресс после КАЖДОГО шага. Не создавать дубликаты PR или строк задач.
2. Перед изменениями прочитать AGENTS.md в mpaykin1/meta6 и в meta6-lab; BIBLIOTEKA.md; rules/06-rabota-ii-s-kodom/BIBLIOTEKA_IGR.md, META_GAMES_SOURCE_ALLOWLIST.md, PERECHEN_OBEKTOV.md, REUSE.md, KONTUR_BEZ_OSHIBOK.md, MNOGORAZOVYE_PROMPTY.md; rules/09-platforma/BIBLIOTEKA_STANOK.md, MCP_AI_GAME_FACTORY_PLAN.md; OSHIBKI.md, ZADACHI.md, ZANYATO.md (если существует), DLYA_CLAUDE.md.
3. Записать в ZADACHI.md одну строку с «Кто: библиотека». Обновить рабочую ветку от main без force-push, не перезаписывая работу других участников. Продолжить существующий PR задачи. Если существующий PR заблокирован после двух попыток — выполнить независимый небольшой шаг; не заводить параллельный каталог.
4. Извлечь фактический состав игр из GitHub и исходных файлов, не из памяти. Исключить *-copy, skin-trainer и прочие учебные игры. Если оригинал содержится в открытом PR, фиксировать «ждёт проверенного слияния», а не «ждёт файл владельца». Два провала одного шага означают остановку и запись Claude с двумя красными run, затем переход к другой игре.

Срез BIBLIOTEKA.md от 10.11.2026 (НЕ считать текущей истиной без повторной проверки): опись 24 позиции, две копии исключены, 13 игр с обнаруженными системами, 0 подтверждённых load_ok; PR #209 — каталожная ветка с двумя неуспешными Chromium. Незавершённая библиотека не объявляется рабочей.

## Семь шагов для каждой игры

Выбрать уникальную игру с наибольшим количеством незакрытых шагов, не трогая занятую чужую ветку. Выполнять по порядку.

1. ИСХОДНИК. Проверить байт-в-байт оригинал в main, принятый Git blob SHA, исходный commit. Нельзя синтезировать замены, менять оригинал или игнорировать различия. Если оригинала нет ни в main, ни в подтверждённой загрузке, записать в DLYA_CLAUDE.md, «Ждёт владельца»: «нужен оригинальный файл игры X», перейти к следующей.
2. ОПИСЬ. Из реальных исходных файлов скриптом извлечь все ассеты и категории с числами. Не описывать по памяти; не включать копии и учебные игры.
3. ПРОИСХОЖДЕНИЕ. У внешних библиотек, шрифтов, звуков, моделей и каждого стороннего компонента зафиксировать источник и лицензию. Если права на переиспользование не подтверждены — пометить и НЕ допускать компонент в живой каталог.
4. СИСТЕМЫ. Взять полный синтаксический узел оригинала (AST) вместе с оригинальными зависимостями и ESM/THREE-версией, без переписывания. Одна система одной игры — один небольшой PR. Отдельный Chromium-контекст с настоящим вводом и непустым canvas/действием подтверждает load_ok; иначе standalone=false и точная причина. Доказательство — GitHub Actions run.
5. АССЕТЫ. Каждый asset_id существует, действительно загружается и имеет ИИ-описание или превью. asset_ok — только после независимой загрузки, не по наличию файла в JSON.
6. MCP. Вызвать на живом MCP list_games, get_system, get_asset (или подтвердить фактическое отсутствие инструмента). Точный ответ и ошибки хранить как ссылку на run/артефакт; не приравнивать чтение JSON к сетевой доступности.
7. ИНДЕКС. Обновить shared/library/index.json и строку игры в BIBLIOTEKA.md только проверенными числами и ссылками. Копии исключить из живого индекса без удаления оригиналов/защищённых архивов.

## Границы безопасности

- Эталоны владельца, существующие games/**, reference/** и работающий игровой код не изменять. Библиотека ссылается и делает точные копии.
- Изменения защищённых .github/workflows/**, scripts/storozha/**, scripts/meta-bot/** и иных защищённых областей — только PR «НУЖЕН CLAUDE», не сливать самим.
- Если PR #209 не принят — не открывать второй catalog-solutions.json. Использовать независимые шаги либо поручить Claude исправление архитектуры извлечения. Существующий PR #218 уже занимается копиями в Library Machine — не делать его дубль.
- Нельзя отключать, ослаблять или обходить STOROZHA, KONTUR, kontur-guard и проверки, а также подделывать успех. Ошибку сначала исправить, внести в OSHIBKI.md и добавить вечную автоматическую ловушку; для новой проверки минимум 3 мутации, включая «обман».
- Не более двух попыток на пару «игра × шаг». После двух неудач — DLYA_CLAUDE.md, раздел «Ждёт Claude», две точные ссылки на красные runs; затем другая игра.
- В main сливать только после зелёных проверок и необходимых согласований. PR с сомнительными правами или защищёнными изменениями самостоятельно не сливать.

## Саморазвитие — строго одно улучшение в конце круга

Выбрать первое невыполненное из automation/biblioteka/PROGRESS.md:
а) сохранить этот текст в automation/prompts/BIBLIOTEKA.md и улучшать контракт;
б) одна система одной игры = один PR + независимая проверка;
в) автоматическая ловушка против *-copy и учебных игр в живом индексе;
г) поиск по назначению на нескольких играх («нужна камера от третьего лица»);
д) игра, собранная только из библиотеки, реально запускается и проходится ботом (FINISH L4);
е) измерение «было → стало» по эталонам, load_ok, asset_ok, MCP-доступности.

Одно улучшение — отдельный PR, ловушка и честный статус CI. По исчерпании списка дописать новое улучшение по самой частой проблеме текущего круга. После каждой ошибки добавить в PROGRESS.md урок и правило, устраняющее причину повторения. Итог круга (игра, шаги, PR, run) — строкой в ZADACHI.md.

## Доказательства и итог владельцу

Каждое утверждение «система грузится», «asset_ok», «в MCP», «слито» подтверждать точным URL + полным 40-символьным SHA, Actions run и числами. До завершения CI статус «не подтверждено», не PASS. Коммиты и PR сами по себе не доказательство выполнения.

Перед ответом посмотреть список оставшегося и сделать всё разрешённое сейчас. В чате писать ТОЛЬКО «Осталось сделать»: сколько уникальных игр ещё не стали полными эталонами (было → стало), мешающие условия и ссылки. Нужный исходник от владельца — одна строка «Загрузи мне игру X (одну)». Claude — одна строка «НУЖЕН CLAUDE: см. DLYA_CLAUDE.md, раздел „Ждёт Claude“, N PR». Если всё подтверждено: «Осталось: ничего — следующее улучшение: …».

## Усиление контракта от 11.11.2026

Проверять PR с отсутствующим в main исходником **перед** обращением к владельцу. Архивную копию, учебную игру и неподтверждённую зависимость нельзя автоматически считать эталоном даже при успешном поиске по файлам. Каждый счётчик в PROGRESS должен иметь ссылку на источник и степень подтверждения. Не переносить исходники из чужих PR и не объявлять статус PASS на основании исходного SHA без живой проверки.

## Обязательная проверка квоты перед новым PR

Перед новым PR проверь свежий GitHub Actions **STOROZHA PR quota**. При переполнении (`LIVE>5`) **не создавать PR**: продолжать существующий PR библиотеки и обозначить блокировку `НУЖЕН CLAUDE`. Запрещено отключать или обходить проверку ради зелёного статуса. Даже после зелёного Chromium система не попадает в `main` или MCP до разрешённого merge.

# БОТ-ПРОХОДЧИК META GAMES — многоразовый промпт

Версия: 2026-11-11. Запуск повторяется без изменений; память о работе хранится только в GitHub.

## Цель

Бот проходит **каждую игру и каждый уровень** обычным вводом игрока. Застревание (2 секунды под
непрерывным вводом без изменения координат) и смерть выявляются немедленно, не по таймауту уровня.
Причину исправляют **в игре**, не скрывают удлинением таймаута или ослаблением проверок.
Никаких телепортов, бессмертия, пропуска уровней, подмены `progress` движением.
PASS/FAIL игры определяет только владелец; бот пишет «технически проходится».

## 0. Возобновление и правила

1. Сначала прочитай `automation/prohodchik/PROGRESS.md`. Если нет — создай.
   Пропусти только игры с подтверждённым полным прохождением **на том же SHA игры**;
   при изменении исходников повтори проходку. После каждого результата сохрани в прогрессе
   название игры, SHA, дату UTC, статус и ссылку на Actions run. Без ссылки не засчитывай.
2. Прочитай до любых изменений `AGENTS.md`, `rules/09-platforma/FINISH.md`,
   `RULES_CHECKLIST.md`, `ZANYATO.md`, `scripts/meta-bot/CONTRACT.md`,
   `OSHIBKI.md`, `KONTUR_BEZ_OSHIBOK.md`, `MNOGORAZOVYE_PROMPTY.md`, `REUSE.md`.
3. Запиши **одну** строку «Кто: проходчик» в `ZADACHI.md`, выбранную часть B — в `ZANYATO.md`.
   Не забирай пункт, если другая ветка активно развивается. Просмотри открытые PR прежде,
   чем создавать аналогичный код. Одна задача — одно небольшое законченное улучшение.
4. Используй `scripts/meta-bot/` и `scripts/platform/` повторно; собственные дополнения
   храни в `scripts/prohodchik/`. Не переписывай ядро, не вноси стороннюю графику.

## 1. Проверки финиша

Работай последовательно: **B2 → B3 → B4 → B5**. Для каждого пункта нужны
`verify-*.mjs`, `mutate-*.mjs` (не менее трёх мутаций, в том числе «обман»)
и **зелёный Actions run** с реальным выполнением. B1 уже обозначен в FINISH,
но его прошлый статус не доказывает B2–B5. Не называй пункт зелёным до проверки.
**Статус в FINISH.md меняет только Claude** — даже после зелёного прогона.

## 2. Полный круг игр

Обнаруживай игры заново из `games/`, реального `list_games` и эталонных каталогов;
игнорируй рабочие папки `*-copy` как отдельные игры. Новые сразу включай в очередь.
Выбирай первую с самым старым доказанным прогоном. Для каждой игры:

- Проверка запуска без HTTP, консольных и JavaScript ошибок.
- ПК: обычные клавиши/мышь. Телефон: реальные касания/джойстик, 390×844,
  портрет. Контроль `scrollX/scrollY` и координат/размера canvas при вводе (FIX).
- **B2:** герой меняет реальные координаты при удерживаемом вводе; изменение
  уровней, анимации, счётчика `progress`, врагов или камеры не заменяет движения.
- **B3:** непрерывный ввод при неподвижном герое 2000 мс → событие STUCK
  с координатами, временем и снимком; не ждать долгого таймаута.
- **B4:** `alive=false` или эквивалент честного состояния → событие DEATH сразу,
  записать место и причину, затем игровое возрождение при наличии видимой кнопки.
- **B5:** пройти **все** уровни последовательно без перескоков и запрещённых обходов;
  сделать повторный независимый прогон для проверки раскладок.
- FPS и ЧИСТЫЙ ЭКРАН — по контракту и правилам; не уменьшать охват проверок.

## 3. Ремонт и защита от повторов

Каждую подтверждённую ошибку: найти первопричину → исправить минимально →
проверить повторной игрой → строка в `OSHIBKI.md` → постоянная ловушка.
Если игра защищена, подготовить отдельный PR «НУЖЕН CLAUDE», записать одну
строку в `DLYA_CLAUDE.md`, не сливать самостоятельно.
Запрещено менять защищённые `.github/workflows/**`, `scripts/meta-bot/**`,
`scripts/storozha/**`, `scripts/kontur/**`, `scripts/zadachi/**`,
`scripts/autofinish/**` и оригиналы игр без согласования Claude.
Существующие STOROZHA/KONTUR проверки не выключать, не обходить, не ослаблять.
Не трогать внешний вид, звук, оружие, камеру и управление вне самой поломки.
Максимум **2 попытки** на неисправность; после двух красных прогонов — одна строка
«Ждёт Claude» со ссылками на оба прогона, затем следующая игра.

## 4. Саморазвитие каждого запуска

После основной части сделать **ровно одно** развитие — отдельный PR с ловушками:
а) сохранить и уточнять этот промпт; б) несколько маршрутов с фиксированным seed;
в) FPS с координатами просадки; г) ЧИСТЫЙ ЭКРАН; д) БЕЗ ПОВТОРОВ;
е) сравнение чисел двух кругов по игре; ж) предложение включить бота на каждом
игровом PR, с передачей защищённого workflow Claude. После списка выбрать
самую частую неисправность и дописать новое развитие в PROGRESS.md.

В `PROGRESS.md` сохрани урок и одно устраняющее причину правило. В `ZADACHI.md`
запиши итоги: проверено / технически пройдено / исправлено / передано Claude,
ссылки на Actions run и PR. Коммить после каждого шага, не храни единственную
точку продолжения в беседе. Дубли прогресса и задач не создавать.

## 5. Требования к доказательствам и ответу

Никаких выдуманных SHA, статусов, браузерных прогонов или скриншотов.
«Технически проходится» = Actions run с логом конца **каждого** уровня плюс
снимок экрана/лог в артефактах. Зелёная мутация сама по себе не доказывает
движение и прохождение реальной игры. Каждый PR обязан иметь один безопасный
следующий шаг, известные ограничения и ссылки.

Владельцу отвечай только «Осталось сделать»: игры с блокерами (одна строка на
игру, со ссылкой), незелёные пункты B и одной строкой
«НУЖЕН CLAUDE: см. DLYA_CLAUDE.md, раздел „Ждёт Claude“, N PR».
Никаких дополнительных отчётов, handoff, evidence-файлов без отдельного запроса.

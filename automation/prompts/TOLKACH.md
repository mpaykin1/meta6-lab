# ТОЛКАЧ МГ и МГЛ — многоразовый промпт

Работай только по актуальным данным GitHub. МГ (mpaykin1/meta6) — только чтение; изменения и PR — в МГЛ (mpaykin1/meta6-lab). Не изменяй принятые игры и защищённые пути без согласования Claude.

## Начало каждого запуска
1. Прочитай automation/tolkach/PROGRESS.md (если отсутствует — создай в рабочей ветке), AGENTS.md, ZADACHI.md, rules/06-rabota-ii-s-kodom/TABLITSA_ZADACH.md, OSHIBKI.md, rules/06-rabota-ii-s-kodom/KONTUR_BEZ_OSHIBOK.md, rules/06-rabota-ii-s-kodom/MNOGORAZOVYE_PROMPTY.md, DOVODKA.md.
2. По 🛑, ⚠, 💤 собери очередь уникальных PR/веток: одна запись на PR независимо от количества строк. Упорядочь по последнему коммиту, сначала МГЛ, потом МГ. Зафиксируй текущие SHA. Обработанные SHA не повторяй; изменившийся SHA — новый кандидат.
3. Прежде чем трогать PR, проверь захват в ZADACHI.md, впиши «Кто: толкач». Не трогай ветку с коммитом моложе 60 минут.

## Один PR — одно действие
- Конфликт: безопасно влей main в ветку без потери изменений; не перезаписывай принятые эталоны.
- Красный CI: изучи лог конкретного job, устрани первопричину в той же ветке, не ослабляя проверок.
- Все обязательные проверки зелёные на текущем SHA, нет конфликтов/защищённых путей: слей по правилам репозитория.
- Подтверждённый дубль или код уже в main: закрой с точным SHA и ссылкой на исходный PR.
- Защищённый путь: не сливай, подготовь безопасное решение и одну строку в DLYA_CLAUDE.md с зелёным run.

После каждого PR немедленно сохрани в PROGRESS.md номер, SHA, действие, UTC и ссылку. В ZADACHI.md меняй итог и ссылку, но не столбец статуса сторожа. После двух реальных неудачных исправлений передай Claude оба красных run. Дедуплицируй раздел «Ждёт Claude» по PR; удаляй уже слитые/закрытые.

## Саморазвитие
За каждый запуск сделай одно отдельное безопасное улучшение отдельным PR: (а) улучшить этот промпт; (б) не создавать дубли строк PR; (в) обновлять ветку из main в начале часа; (г) счётчик 🛑 до/после; (д) топ-3 причин зависаний и профилактика; (е) предложить Claude защищённую автоматизацию дедупликации сторожа. Когда список исчерпан — добавь новую меру по самой частой причине.

Каждая новая ошибка требует OSHIBKI.md и работающей ловушки КОНТУР К1–К10. Никаких вымышленных SHA, зелёных CI или слияний. Записывай урок и следующее правило в PROGRESS.md. Итог запуска — в ZADACHI.md.

Владелец получает только «Осталось сделать»: 🛑 было → стало, блокеры со ссылками и одной строкой «НУЖЕН CLAUDE: см. DLYA_CLAUDE.md, раздел „Ждёт Claude“, N PR». Без доказательства действие не считается выполненным.

## Инфраструктурный красный CI — не путать с дефектом
- Читай лог **упавшего job** до изменения кода. Если шаг не дошёл до теста из-за DNS, `apt`, GitHub API rate limit или сетевой ошибки, это красный CI, но не доказанный дефект проверяемого изменения. Пример: [B1 43035572985](https://github.com/mpaykin1/meta6-lab/actions/runs/43035572985) — `Temporary failure resolving azure.archive.ubuntu.com` во время установки Playwright-зависимостей.
- Не отключай и не ослабляй job, не меняй эталон или игровой код под инфраструктурный сбой. Разрешён один повтор только упавших jobs после повторной проверки HEAD. Ожидающий, отменённый и повторно упавший run **не зелёный**.
- Такой повтор не является попыткой исправить код и не расходует лимит двух попыток К2. При повторной сетевой ошибке отметь внешний блокер со ссылкой на оба run и переходи к следующему PR; не передавай Claude как ошибку исходников.
- При параллельной записи `ZADACHI.md` повторно прочитай blob SHA и найдите существующую строку по repo+PR. Захват меняет только владельца существующей строки, не создаёт дубль и не меняет столбец статуса сторожа.

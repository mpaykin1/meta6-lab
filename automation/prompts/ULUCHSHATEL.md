# УЛУЧШАТЕЛЬ ИГР ПО ПРАВИЛАМ — многоразовый промпт

**При каждом запуске сначала читать свежую версию ЭТОГО файла из main, затем
`automation/uluchshatel/PROGRESS.md`.** После обрыва продолжать по GitHub,
не повторяя пары «игра × правило» с подтверждённым PR, SHA и зелёным Actions.
Рабочая площадка — только `mpaykin1/meta6-lab`; `mpaykin1/meta6` — только чтение,
перенос подтверждённого туда делает Claude. Нельзя завершать запуск словами
«делать нечего»: минимум одно реальное улучшение с коммитом/PR.

## Цель
Все игры из актуального каталога довести до 14 правил
`rules/09-platforma/RULES_CHECKLIST.md`: ЧИСТЫЙ ЭКРАН,
ПОСТЕПЕННО, новинки вперемешку, ПОНЯТНАЯ ПОЛЬЗА,
БЕЗ ПОВТОРОВ, FIX, UNIVERSAL U1–U6, ЗВУК, ЛОР,
ВИДИМО И ЭКОНОМНО, работа ИИ с кодом, RETENTION,
бот-ручка, оптимизация рендеринга. Только добавление:
не убирать ассеты, не ломать принятые владельцем механики.

## Вход до правки
1. Прочитать `AGENTS.md`, весь `RULES_CHECKLIST.md` с
   «Известными расхождениями» и «Статусом по играм»,
   полный текст выбранного правила из `rules/01…07`,
   `rules/09-platforma/BEZ_REKLAMY.md`,
   `docs/PLAYGAMA_RETENTION.md` для №12;
   `REUSE.md`, `META_GAMES_SOURCE_ALLOWLIST.md`,
   `NE_MENYAT_NEZAPROSHENNOE.md`, `PERECHEN_OBEKTOV.md`,
   `KONTUR_BEZ_OSHIBOK.md`, `MNOGORAZOVYE_PROMPTY.md`, `OSHIBKI.md`.
2. Открыть `automation/uluchshatel/PROGRESS.md`, исключить обработанные
   пары по датам/PR/SHA. Если файла нет — создать в своей ветке.
3. До создания ветки, захвата или любой правки игры проверить `ZANYATO.md`,
   `ZADACHI.md`, последний коммит игры и **ВСЕ** открытые PR, включая
   **каждую страницу списка их изменённых файлов**. Запустить
   `node scripts/uluchshatel/preflight.mjs games/<slug> lab/<ветка>`.
   Список из 5–10 PR или поиск по названиям **запрещены**: PR #234
   («каталог без рекламы») изменяет `games/broken-city-copy/index.html`,
   хотя название PR не содержит имя игры. При неполной пагинации,
   GitHub HTTP 403, отсутствии запуска проверки, пересечении PR,
   чужом замке или коммите игры моложе 60 минут — **НЕ ТРОГАТЬ игру**.
   Работать над независимым улучшением алгоритма, не над занятым кодом.
   Не создавать новую `*-copy` папку (К12), не имитировать зелёный run.
   Проверка безопасности: `verify-preflight.mjs` и `mutate-preflight.mjs`
   включают ловушку позднего PR и второй страницы файлов.
4. Захватить свободную игру строкой «Кто: улучшатель» в `ZADACHI.md`
   с игрой/правилом и `ZANYATO.md`. Для занятых игр замок НЕ присваивать.
   Не трогать чужие строки.

## Выбор
Сначала доказать метод на `games/skin-trainer` или уже существующей
рабочей копии `*-copy`; остальные игры — только после зелёного
результата тренировки. Дальше брать игру, которую дольше всего не
улучшали, и первое «не сделано», затем «частично». Одна игра и одно
правило за запуск; следующая пара допустима после завершения первой.

## Круг улучшения
1. До правки собрать `docs/INVENTORY_<игра>.md` **из реального кода скриптом**:
   источники, количества ассетов, уровней, механик, звуков; замерить FPS p95
   и прохождение META BOT до изменения. Без измерения писать «нет данных».
2. Вносить выбранное правило только добавлением по столбцу «Что должно быть
   в игре», брать готовые реализации и ассеты только из той же игры
   или `META_GAMES_SOURCE_ALLOWLIST.md`. Не трогать героя, 21 оружие,
   управление, камеру, физику, графику, стиль и прочее вне правила.
3. Во всех версиях META GAMES запретить рекламу и её SDK
   (`BEZ_REKLAMY.md`); для №12 — бесплатное возрождение по кнопке
   и мгновенное «Ещё раз», без рекламы. Не изменять версию Playgama.
4. Гаснущие сообщения сохранять. Конфликт каркаса проверки
   ЧИСТОГО ЭКРАНА эскалировать как «ждёт правки каркаса:
   гаснущие сообщения». `skipChecks` всегда `[]`.
5. По столбцу «Как проверить» — `verify-*.mjs` и
   `mutate-*.mjs` с 3 ловушками, включая «обман»; CI Actions
   на текущем SHA, телефон 390×844 с тачем и ПК, повторный запуск,
   FPS p95 не хуже baseline, META BOT проходит. Проверять опись
   «было N → осталось N, потеряно 0»; чисел не придумывать.
6. После зелёного подтверждения обновить только строку игры
   в `RULES_CHECKLIST.md` со ссылкой на run. Ставить
   «технически внесено», не PASS/FAIL: их ставит только владелец.
7. Защищённые `games/**`, эталоны, `scripts/meta-bot/**`,
   `.github/workflows/**` самостоятельно не сливать:
   предложить PR «НУЖЕН CLAUDE» и одну строку
   `DLYA_CLAUDE.md` → «Ждёт Claude» с PR, игрой,
   правилом, эффектом для игрока и ссылкой на зелёный run.

## Ошибки, остановки и устойчивость
- Ошибку исправить до отчёта; каждая подтверждённая ошибка —
  строка в `OSHIBKI.md` и автоматическая ловушка по К1–К10.
- Не отключать STOROZHA/KONTUR/kontur-guard/META BOT, не ослаблять проверки.
- Не более двух настоящих попыток на пару. После двух красных run
  — `DLYA_CLAUDE.md` и переход к следующей паре.
- После **каждого шага** коммитить в свою ветку
  `PROGRESS.md`: игра, правило, шаг, UTC, ссылка-доказательство;
  при новом запуске читать и пропускать уже сделанное.

## Саморазвитие, обязательно в конце круга
Брать **одно первое невыполненное**:
а) сохранять/улучшать этот промпт;
б) `rules/09-platforma/RECEPTY/<номер>.md` с точными источниками;
в) общий модуль в `shared/` после 2 одинаковых внедрений;
г) матрица игр × 14 правил и изменение счёта «было → стало»;
д) измеритель резкости и соотношения harmonic/dis = 1:0.5;
е) проверка последовательности новинок (нет подряд одинакового,
после врага — польза). Дальше — новая идея по главному препятствию,
зафиксированная в PROGRESS.md.
Каждое самоулучшение — отдельный PR с ловушкой и зелёными CI.
В PROGRESS.md записать «Урок» и одно правило предотвращения,
в ZADACHI.md — итог: игра, правило, PR, Actions.

## Только «Осталось сделать»
Владельцу писать кратко: неготовые пары «N из M», блокер и ссылку;
если нужен ручной игровой тест — одна игровая ссылка и одно изменение.
Claude — одной строкой: «НУЖЕН CLAUDE: см. DLYA_CLAUDE.md,
раздел „Ждёт Claude“, N PR». Утверждения о готовности,
FPS, отсутствии потерь, PASS/FAIL без Actions и точного SHA запрещены.

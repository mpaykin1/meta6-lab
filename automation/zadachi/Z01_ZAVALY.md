## Шаги (сколько успеешь; после каждого PR — строка в PROGRESS.md)
Иди по открытым PR от самого старого. Для каждого — ровно одно решение:
1. **Уже в main** (все файлы PR совпадают с main или работа повторена другим PR) → закрыть с комментарием `уже в main: <SHA>`.
2. **Дубль** другого открытого PR (та же ветка-тема, например `lab/razbor-zavalov` дважды) → оставить новейший, остальные закрыть с ссылкой на оставленный.
3. **Конфликт с main** → влить свежий main в ветку, снять конфликт (берёшь main для таблиц-сводок ZADACHI/DISPETCHER/TOLKNUT/STATUS — их пересоберёт сторож), запушить.
4. **Красная только Vercel-квота** → влить main (там `vercel.json` выключает сборки веток), проверка исчезнет. Не чинить Vercel.
5. **Больше 5 файлов** → разбить на 2–3 PR по смыслу; исходный закрыть со ссылками на новые.
6. **Всё зелёное, защищённого нет** → слить (правило 12 GPT.md).
7. **Зелёное, но защищённое** → заголовок `НУЖЕН CLAUDE: …`, строка в DLYA_CLAUDE.md.
8. **Эталон с OWNER PASS** (#283, #322, #325 и подобные) → по карточке [Z03](Z03_ETALONY.md).
9. **Брошенный эксперимент** (💤 > 2 суток, нет зелёного прогона, нет ссылки в FINISH) → закрыть с комментарием «заброшено, ветка сохранена: <ветка>» (ветку не удалять — работа не теряется).

Закрывать разрешено только по пунктам 1, 2, 5, 9 и всегда с комментарием-ссылкой.

## Опыт (дописывает исполнитель: одна строка «что случилось → как обойти», со ссылкой)
- 17.11 Claude: [#331](https://github.com/mpaykin1/meta6-lab/pull/331) — 15 файлов и конфликт: разбить (п.5) на PR без workflow (dispetcher build.mjs + его тесты; TOLKACH/SLIYANIE доки; karta-sil) — их сливать самому; отдельный PR только с `.github/workflows/additive-merge-preflight.yml` + его verify/mutate — `НУЖЕН CLAUDE`.

- Для проверки дубля сначала сравни `head.sha`, `base.sha` и список изменённых путей у обоих PR; одинаковая тема или похожее название **не** доказывают дубль. Перед закрытием проверь фактическое наличие всех изменений в `main` по diff и укажи SHA подтверждения. Это предотвращает потерю работы при массовом разборе.

- При независимой приёмке PR комментарий `COMMENT` не равен `APPROVED`: перед слиянием сверить состояние review, актуальный HEAD, конфликты и обязательные проверки. Пример: [рецензия #361](https://github.com/mpaykin1/meta6-lab/pull/361#pullrequestreview-5933636353) зафиксировала конфликт, а не разрешение на слияние.

- При поиске открытых PR не доверяй выдаче, в которой по запросу `is:pr` возвращаются `issues/` вместо `pull/`: это неполные данные, не основание закрывать PR или утверждать, что очередь пуста. Повтори проверку через список pull requests с полями `number`, `state`, `draft`, `head.sha` и `mergeable`; при недоступности API оставь точный блокер, не меняй чужие ветки.

- Проверка `combined status` с пустым `statuses` не означает отсутствие CI: отдельно запросить workflow runs по точному `head.sha`, сверить `conclusion` каждого обязательного workflow и не принимать старые прогоны за текущие. Пример: [HEAD 6d9b893](https://github.com/mpaykin1/meta6-lab/commit/6d9b8933677902b11d818a2aa9816501bbfd72ea), [META GAMES guard](https://github.com/mpaykin1/meta6-lab/actions/runs/44027903922).

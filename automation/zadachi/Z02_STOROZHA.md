## Зачем
Система «что сделано / в работе / зависло» уже есть (ZADACHI watch, ZANYATO watch, DISPETCHER, TOLKNUT, STATUS.md), но местами врёт: в `automation/status.json` все пункты финиша «не подтверждено — GitHub недоступен» со старыми ссылками; в DISPETCHER бывает «undefined»; прогоны на main часто `cancelled`. Если сводка врёт, все промпты выбирают не ту задачу.

## Готово, когда
Три запуска подряд: STATUS.md и status.json показывают те же статусы пунктов финиша, что FINISH.md; нет «undefined» / «нет данных» там, где GitHub данные даёт; сторожа на main не отменяются (`cancelled`) друг другом.

## Шаги
1. Сравни status.json с FINISH.md построчно. Найди, где сборщик берёт «GitHub недоступен» (скорее всего читает старые run ID без токена или превышает лимит API) — почини чтение: брать статус из FINISH.md, а прогоны — через `GITHUB_TOKEN` Actions.
2. Отмены `cancelled`: у сторожей, которые пишут в main, — `concurrency` с `cancel-in-progress: false` и одна группа на файл, а не на весь репозиторий (#299).
3. «undefined» в заголовках — найди место сборки строки, ставь заглушку `(без названия)` + ловушку.
4. Таблиц не добавлять. Если две таблицы показывают одно и то же — сделай одну источником, во второй оставь ссылку.
5. Почти всё здесь — защищённые файлы: доведи PR до зелёного, `НУЖЕН CLAUDE:` в заголовке, строка в DLYA_CLAUDE.md.

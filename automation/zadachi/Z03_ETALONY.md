## Зачем
Владелец одобрил эталоны (Павший великан, Акварельный паровоз, Чернильный оскал…). В МГ они уже лежат в `reference/…`, а их PR в МГЛ (#283, #287, #322, #325 и подобные) висят открытыми с конфликтами и красными проверками.

## Готово, когда
Для каждого эталона из раздела «INK — эталон» в [AGENTS.md МГ](https://github.com/mpaykin1/meta6/blob/main/AGENTS.md): папка `reference/<имя>/` в МГЛ побайтно совпадает с МГ, ссылки МГ и МГЛ отвечают 200, его старый PR в МГЛ закрыт с комментарием «эталон уже в main: SHA».

## Шаги
1. Список эталонов — из AGENTS.md МГ (строки «Эталон **…** (OWNER PASS …)»).
2. Для каждого: сравни `reference/<имя>/` МГ и МГЛ (хеши файлов).
   - Совпадает → закрой его висящий PR в МГЛ с комментарием и SHA.
   - В МГЛ нет или отличается → скопируй из МГ **как есть** (эталон не менять), один PR на эталон, слей (это копия одобренного — не новая работа).
3. Проверь обе ссылки на 200, добавь в LINKS.txt.
4. Эталон не ограничивает новое: если игре нужен «новый поезд» — делается новый, эталон только предлагается.

## Саморазвитие (после основной работы, обязательно одно)
Сделай скрипт `scripts/platform/verify-etalony-sync.mjs` (+ мутация «изменён 1 байт эталона»), чтобы рассинхрон эталонов ловился автоматически.

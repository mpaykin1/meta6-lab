# META GAMES — Эталон спецификации автономного игрового ZIP (v1.0)

Статус: **нормативный стандарт для новых игр META GAMES**. Дата: 2026-11-08. Применяется к 2D, 2.5D, 3D voxel/pixel-art играм, в том числе Train in the Fog.

## 1. Результат
Один ZIP с папкой игры, исходными редактируемыми ассетами, оптимизированными runtime-ассетами, анимациями, материалами, коллизиями, сценами, звуком, сюжетом и **работающим автономным index.html**. После распаковки открывается двойным нажатием без сервера, CDN, API и сети. Архив только с картинками **не считается готовой игрой**.

Плановый масштаб Train in the Fog: **640 уникальных базовых ассетов**, ориентировочно **2500–4000 файлов/кадров с вариантами**. Эти цифры — целевой объём контента, а не универсальный минимум для всех игр. Уникальные объекты, кадры анимации, ракурсы и LOD считать отдельно.

## 3. Форматы
| Сущность | Runtime | Исходник/метаданные |
|---|---|---|
| 2D sprites | PNG RGBA8 sRGB, WebP lossless | PNG + JSON |
| 2D animation | PNG spritesheet | JSON frames/FPS/events |
| 2.5D characters | PNG directional sheets | JSON, опционально GLB |
| Voxel meshes | glTF 2.0 GLB | VOX + GLB |
| 3D animation | GLB clips | animation metadata |
| PBR textures | PNG/WebP | albedo, normal, roughness, metallic, emissive, alpha, AO |
| Backgrounds/tiles | PNG/WebP | parallax and tile metadata |
| Shaders | GLSL ES 3.00 | embedded at build time |
| Sound/music | OGG, fallback MP3 | audio manifest |
| Fonts | WOFF2 or bitmap atlas | license |
| Physics/levels/story | embedded JSON-compatible data | JSON UTF-8 |

## 4. Pixel-art
- PNG RGBA8, sRGB, прозрачность без фоновых прямоугольников; nearest filtering, integer pixel alignment.
- Tiles: 16×16, 32×32, 64×64; characters: 64×96 или 96×128; props: 128/256; UI: 32/64/128.
- Атлас для мобильного профиля до 2048×2048; padding/extrusion 2–4 px против bleeding.
- Pivot у персонажа — ступни, normalized [0.5,1.0]; у предметов — явная опора; единый pixelsPerUnit (начальное значение 32).
- Стабильный bounding box и pivot между кадрами. Никакого случайного bilinear smoothing.

## 5. Animation
Для каждого клипа: id, assetId, sheet/model, frameWidth, frameHeight, frames/rects, fps, loop, pivot, events, transition states.
Рекомендации: idle 8 FPS/8–16 кадров; walk 12/8–12; run 16/8–16; jump 12/8–12; ghost 12/12–24; doors 12/8–16; rain 12–24/8–16.
2.5D directional sets: N, NE, E, SE, S, SW, W, NW; mirror только при отсутствии асимметричных деталей. Для GLB — именованные animation clips и контролируемые transitions.
```json
{"id":"ANIM_PLAYER_WALK","asset":"CHR_PLAYER_001","sheet":"assets/spritesheets/player/walk.png","frameWidth":96,"frameHeight":128,"columns":8,"rows":1,"frames":8,"fps":12,"loop":true,"pivot":[0.5,1],"events":[{"frame":2,"event":"footstep"},{"frame":6,"event":"footstep"}]}
```

## 6. Voxel/3D
- GLB glTF 2.0, Y-up, правосторонняя система, объект смотрит вдоль -Z, 1 unit = 1 метр, origin у основания; текстуры внутри GLB.
- GLB без обязательных внешних Draco/KTX2-декодеров, если они не включены локально.
- Ориентиры на объект: small prop 50–500 tris; tree 300–2000; character 1000–5000; wagon 3000–12000; locomotive 8000–25000; building 2000–15000.
- LOD по необходимости, отдельно простые collision primitives, не использовать подробную render mesh как обязательную физическую форму.
- Поезд: независимые колёса/тележки, двери, дворники, сцепки, фары, звуковые sockets, посадка, камера машиниста, повреждения.
```json
{"id":"TRAIN_LOCOMOTIVE_001","type":"model","path":"assets/models/glb/locomotive.glb","units":"meters","forward":"-Z","scale":[1,1,1],"collision":"locomotive_collision","animations":["wheels_rotate","doors_open","doors_close","wipers","engine_idle"],"sockets":{"headlight":[0,3.1,-7.2],"driver_camera":[0,2.7,-2.1],"front_coupler":[0,0.8,-7.8],"rear_coupler":[0,0.8,7.8]}}
```

## 7. Materials, lighting, weather
PBR channels: baseColor, normal, roughness, metallic, emissive, alpha, AO. Стартовые metallic/roughness: wet rails 0.9/0.15; rusty metal 0.7/0.8; wet concrete 0/0.3; old wood 0/0.85; glass 0/0.05; painted locomotive 0.4/0.35. Эти значения художественные пресеты, не физическая гарантия.
Headlight: spotlight + emissive + volumetric cone/fog shader + bloom + wet rail reflections; у ламп отдельные light sockets. Эффект volumetric нужно реализовать в renderer: одного JSON-флага недостаточно.
Rain: instanced particles, puddle ripples, droplets on branches/lens, mist; dynamic weather profiles. Mobile: 1–2 shadow-casting lights максимум, остальные emissive/glow.

## 8. 2.5D scene layers
Четыре обязательных слоя: background (sky, distant hills/forest), midground (train, rails, station), foreground (wet grass, branches, puddles), screen_fx (fog, rain, bloom, vignette, UI). У каждого: parallax, draw order, camera offset, scale, lighting/fog policy. `depth` в метаданных 2D означает draw order, не обязательно мировую Z-координату.

## 9. Physics/interactions
Объект классифицируется как static/dynamic/trigger/decorative/interactive. Коллизии: box/capsule/sphere/compound/convex, размеры в метрах, center, solid, collision layer/mask, trigger event. Отдельные входы в вагоны, лестницы, платформы, двери, стрелки, опасности, навигация NPC, точки взаимодействия.
```json
{"id":"COL_STATION_BENCH_001","asset":"PROP_BENCH_001","shape":"box","center":[0,0.45,0],"size":[1.8,0.9,0.6],"solid":true,"interactable":true,"interaction":"inspect_bench"}
```

## 10. Registry and stable naming
Файл `asset-manifest.json`: schemaVersion, packId, assets[].id/category/type/path/required/animated, plus optional size, pivot, material, collision, animations, sockets, tags, source/license. ID не меняется при замене изображения.
```json
{"schemaVersion":"1.0","packId":"meta_games_train","baseAssetTarget":640,"coordinateSystem":"right-handed-y-up","unitScale":1,"assets":[{"id":"TRAIN_LOCOMOTIVE_001","category":"train","format":"glb","path":"assets/models/glb/locomotive.glb","required":true,"animated":true},{"id":"CHR_PLAYER_001","category":"characters","format":"png","path":"assets/sprites/characters/player.png","required":true,"animated":false}]}
```
Файлы: lowercase ASCII snake_case, например `train_locomotive_001.glb`, `player_walk_ne_sheet.png`, `station_platform_001_collision.json`. Пути относительные, регистр строго совпадает, никаких placeholder/URL.

## 11. file:// offline guarantee
Нельзя полагаться на `fetch()` локальных JSON/GLB, ES module imports, внешние CDN или локальный сервер: браузеры ограничивают `file://`. В сборке встраивать JS, JSON, GLSL и GLB bytes как данные в `index.html`/синхронно подключённые classic scripts; декодировать GLB из ArrayBuffer в памяти через локально встроенный loader либо заранее преобразовать в JS-геометрию. PNG/audio допускается грузить относительными путями через HTMLImageElement/Audio при проверке на целевых браузерах. Для максимальной переносимости можно встроить и их. Не использовать внешние network dependencies.

## 12. Mobile budgets (ориентиры, не гарантии)
iPhone 11: 30–60 FPS, адаптивный render resolution; atlas ≤2048; active particles ~500–2000; visible triangles ~100k–300k; draw calls желательно ≤100–150; shadowed lights 0–2. Ограничивать overdraw, postprocessing и GPU memory; audio запускать после пользовательского жеста.

## 13. Acceptance
1. Все заявленные файлы существуют, не пустые, читаются и имеют реальные пиксели/геометрию/клипы.
2. Реестр разрешается полностью, нет duplicate ID, broken paths, dangling dependencies.
3. Размеры, pivots, координаты, ориентации, collisions и sockets согласованы.
4. Анимации проигрываются без скачков, работают события и переходы.
5. Реально работают поезд, движение игрока, управление пальцем/клавиатурой, взаимодействия, сцены, погода, свет, сюжет.
6. После распаковки `index.html` работает **без сервера и интернета** на целевых платформах. Проверять отдельно iOS Safari и desktop browsers: открытие локальных файлов на iOS зависит от приложения и его политики.
7. Нет placeholder UI, пустых карточек, неработающих кликов; читаемый полный лор открывается в полноэкранном режиме.
8. Архив сохраняет исходные ассеты и лицензии; визуальная сборка воспроизводима.

## 14. Художественный эталон Train in the Fog
Кинематографичный тёмный pixel/voxel art: густой объёмный туман, холодная синевато-серая палитра, тёплые окна, мокрые рельсы, отражения в лужах, прожектор локомотива, лесные силуэты, дождь, минималистичный интерфейс. Не подменять художественные объекты простыми заглушками.

**Правило:** при создании новых игр использовать этот стандарт как контракт форматов и приёмки, адаптируя количество ассетов и игровые механики под проект.

## 15. ОБЯЗАТЕЛЬНЫЙ ХУДОЖЕСТВЕННЫЙ GATE — CINEMATIC VOXEL NOIR (Train in the Fog)

**Приоритет:** этот раздел имеет преимущество перед любыми более ранними указаниями «простая пиксельная графика», «быстрые 20 ассетов», «достаточно SVG», «достаточно GLB» и любыми числовыми оценками готовности. Художественные референсы владельца — три вертикальных эскиза: (1) локомотив у платформы, свет прожектора, мокрые шпалы; (2) поезд в лесу, сигнальная мачта, лужи и дальний холм; (3) поезд в плотном тумане, боковая платформа, луч вправо вверх. **Не подменять их случайными изображениями из поиска.** Референсы R1/R2/R3 размещены в `assets/train-in-the-fog/references/` и должны быть явно указаны в `asset-manifest.json` по фактическим путям из документа `REFERENCE_FRAMES_R1_R2_R3_RU.md`. Пока нет сопоставимых игровых кадров — блокировать утверждение «соответствует эталону».

### 15.1. Художественная идентичность
- Не «плоский pixel-art» и не «геометрическая иллюстрация»: **кинематографический объёмный voxel art с пиксельной детализацией**, мрачный фотореалистичный свет, физически читаемая материальность, глубина, многослойная композиция.
- Перспективная 3D-камера на уровне рельсов, диагональные ведущие линии, локомотив на среднем плане, сильный силуэт, масштаб, отрицательное пространство тёмного неба; ракурсы строго сравнивать с эталонами.
- Цвет: холодный почти чёрный сине-графитовый/сланцевый мир; локальные тёплые янтарные окна и фонари; бело-холодный прожектор. Без кислотного неона, мультяшной насыщенности, плоских градиентных заливок и «треугольного прожектора».
- Реальные объёмные детали: локомотив с фасками, тележками, решётками, фарами, рамами окон и вагонными сочленениями; рельсы с профилем, крепежом, деревянными шпалами, щебнем; станция с навесом, опорами, скамьями, светильниками; рельефная земля, кустарник, голые деревья и хвойный лес.
- Воксельная ступенчатость должна читаться в силуэтах и деталях, но **не** превращать весь кадр в грубые одинаковые кубы. У каждого материала собственный масштаб детализации.

### 15.2. Обязательный пайплайн каждого крупного ассета
1. **Reference breakdown:** зафиксировать силуэт, пропорции, конструктивные элементы, материалы, масштаб, цветовые зоны, световые источники и положение в кадре.
2. **Геометрия:** создавать настоящую редактируемую 3D-модель (GLB + исходник), с фасками/ступенчатыми воксельными деталями и логическими подузлами; плоский PNG не заменяет модель локомотива, здания, рельсов или сигнала.
3. **Материалы:** PBR-каналы albedo, normal (если нужен), roughness, metalness, emissive; физически убедительные мокрый металл, ржавчина, грязь, древесина, стекло и краска. Не требовать отдельной текстуры для каждого объекта, если достаточно общего атласа.
4. **Освещение:** локальные emissive окна, лампы и фары; направленный прожектор с **плавным рассеиванием в объёмном тумане**, мягкой границей и затуханием по расстоянию; динамическая экспозиция, умеренный bloom, тени, холодный ambient.
5. **Мокрая сцена:** puddle masks, вариации roughness, зеркальные блики на рельсах и воде, рябь, следы дождя, отражения источников света. Допустимы оптимизированные screen-space/fake reflection методы, если кадр остаётся убедительным.
6. **Анимация:** для локомотива — движение, колёсные тележки, лёгкие вибрации, дым/пар, фары; для станции — мерцание ламп, сигналы; для мира — дождь, капли с ветвей, туман, лёгкое движение растительности. Кадры анимации без визуальных изменений не засчитывать.
7. **Интеграция:** модель должна реально отрисовываться **в основной игровой сцене**, с верной перспективой, материалами, освещением, коллизиями и управлением. Отдельный 3D-viewer не равен игровой интеграции.
8. **Проверка кадра:** делать фактический скриншот из игры в контрольном ракурсе и сравнивать рядом с конкретным эскизом, исправляя геометрию, свет, атмосферу и композицию до следующей партии.

### 15.3. Обязательная структура кадра
- **Глубина:** тёмное небо, дальний лес/холмы/башня, несколько слоёв тумана и атмосферная перспектива.
- **Средний план:** локомотив и вагоны, платформа, навес, сигнальная мачта, фонари, забор, здания; локальные источники света.
- **Передний план:** детальные рельсы/шпалы, мокрый балласт, лужи с отражениями, трава, камни, ветви, мох, грязь.
- **Экранные эффекты:** физически мотивированный дождь, лёгкий bloom, зерно/дизеринг при необходимости, адаптивная экспозиция. UI не должен заслонять композицию.

### 15.4. Запрещённые замены и ложные признаки готовности
- **ЗАПРЕЩЕНО** считать готовым локомотив из прямоугольников, луч света в форме непрозрачного треугольника, деревья из одинаковых треугольников, рельсы из линий, SVG-макеты, примитивные кубики и геометрические иконки.
- **ЗАПРЕЩЕНО** считать наличие 20 PNG, 20 GLB, 80 кадров, JSON или ZIP доказательством соответствия референсам.
- **ЗАПРЕЩЕНО** объявлять 85–100% художественной готовности без просмотра реального игрового кадра и сравнения с эталонами.
- Не выдавать рендеры-превью моделей или статичные изометрические картинки за интегрированный в игру 3D.
- Не переходить к массовому производству 640 позиций, пока контрольная сцена «поезд + рельсы + платформа + лес + туман + свет» не прошла художественную приёмку.

### 15.5. Обязательная контрольная сцена перед серийным выпуском
Минимальный вертикальный кадр **9:16**: локомотив с минимум одним видимым вагоном; трёхмерные рельсы в перспективе и мокрые шпалы; платформа с навесом и фонарём; сигнальная мачта; деревья/лес; лужи и отражения; несколько глубин тумана; прожектор, рассеивающийся в тумане. Проверять также горизонтальную композицию и мобильную адаптацию. **Вначале художественно завершить эту сцену, потом выпускать серии ассетов.**

### 15.6. Оценка готовности ассетов
**Не присваивать проценты без подтверждённых измерений.** Для каждой позиции считать 100 баллов:
- 30 — сходство с авторским эскизом (силуэт, масштаб, композиция, палитра, настроение);
- 25 — 3D-геометрия, PBR-материалы, визуальные детали;
- 20 — реальная интеграция в игровую сцену, коллизии, корректные координаты;
- 15 — необходимые анимации, взаимодействия и световые события;
- 10 — проверка работы и бюджета производительности на целевых устройствах.

Непроверенные пункты получают **0 подтверждённых баллов**, а не «оценку на глаз». Отдельно указывать: **готовность партии** (средневзвешенная по ассетам) и **готовность всей игры** (включая отсутствующие позиции из списка 640). Если нет доступа к iPhone, мобильные 10 баллов не подтверждены; desktop-проверка не заменяет iOS.

**Правило выпуска:** готовый ассет = корректный исходник + runtime-формат + материалы + нужные анимации + параметры + реально работающий объект в сцене + визуальная приёмка по эталону. Иначе статус WIP, даже если файл существует.


## 16. TRAIN IN THE FOG — НЕПЕРЕГОВОРНЫЙ ВИЗУАЛЬНЫЙ КАНОН ТРЁХ ЭСКИЗОВ

**Цель:** не «похоже по жанру», а максимально близкое воспроизведение художественного языка, постановки камеры и освещения трёх предоставленных вертикальных эскизов. Техническая корректность glTF, число мешей, наличие PBR и работа просмотрщика **не заменяют** визуальное сходство. Если итог выглядит как набор кубов, примитивный low-poly или CAD-превью, художественная приёмка провалена.

### Кадры-эталоны и неизменяемые признаки

**R1 — поезд у платформы:** вертикальный кадр 9:16; камера низко над мокрыми шпалами; две блестящие рельсовые нити крупно в переднем плане сходятся к локомотиву в средней глубине; массивный тёмный фронт поезда слева от центра; белый круглый верхний прожектор и два небольших нижних огня; сильный широкий световой луч по диагонали вправо-вверх; справа деревянный платформенный навес, опоры, скамья и тёплые квадратные фонари; слева силуэты голых ветвей; лужи, грязь, мокрый гравий и отражения; фон исчезает в серо-синем тумане.

**R2 — лесной перегон:** вертикальный кадр 9:16; огромные мокрые голые ветви с каплями нависают слева сверху, формируя рамку; тёмный поезд в средней дистанции, слева от оси; луч главного прожектора уходит вправо-вверх через многослойную дымку; справа высокий железнодорожный семафор с круглой тёплой лампой, лестницей, кронштейнами и проводкой; рельсы и шпалы в нижней половине кадра; на переднем плане лужи, высокая мокрая трава, камни и столбик «127»; дальние хвойные силуэты, домик с освещёнными окнами и радиомачта на холме.

**R3 — поезд из тумана:** вертикальный кадр 9:16; поезд частично поглощён густой холодной дымкой; слева у края платформы семафор, свисающая лампа и силуэт навеса; прожектор в центре с ярким ядром и очень широким, мягким, неоднородным лучом вправо-вверх; пара малых нижних огней; мокрые рельсы диагонально идут из нижнего правого угла в глубину; на плитке платформы небольшие световые отражения; почти монохромная графитовая палитра с редкими тёплыми источниками света.

### Обязательные художественные ограничения

- **Силуэт поезда:** широкий тяжёлый фронт, читаемая крыша с выступами, окна кабины и вагонов с тёплым свечением, корпус с секциями, боковые тележки, решётки, стыки панелей, заклёпки, ступени, сцепки и грязь. Силуэт должен оставаться узнаваемым в тумане. Нельзя подменять состав одним прямоугольным параллелепипедом.
- **Воксельная пластика:** мелкие ступенчатые края и блоковые детали сочетаются с реалистичными пропорциями и многослойными материалами. Не использовать чрезмерно крупный воксель, который уничтожает силуэт, не рисовать гладкие пластиковые поверхности.
- **Рельсы:** две непрерывные металлические головки с заметным профилем, поперечные деревянные шпалы с неидеальным шагом, крепёж, насыпанный камень, локальная грязь и вода между шпалами. Нужны узкие яркие отражённые блики вдоль головок.
- **Станция и семафор:** реальная конструкция навеса с толщиной кровли, балками, опорами, кронштейнами; семафор с отдельными корпусом фонаря, линзой, козырьком, лестницей и крепежом. Светильники — маленькие тёплые островки света в холодной сцене.
- **Физика света в изображении:** очень яркий почти белый центр прожектора, плавный спад яркости и рассеяние на неоднородном объёмном тумане; луч не должен иметь чёткую треугольную границу. Локальные ореолы и bloom, частичное перекрытие луча ветвями/архитектурой, мягкая засветка близких поверхностей.
- **Туман и глубина:** не менее трёх различимых глубинных слоёв, ближние предметы контрастнее дальних, поезд частично скрыт дымкой, дальний лес почти растворён; туман не должен быть одним плоским серым прямоугольником или полностью скрывать композицию.
- **Материалы:** холодный мокрый металл с ржавчиной и грязью, тёмное влажное дерево, мокрый балласт, стекло окон, камень, лужи с нарушенными рябью отражениями. Текстурная неоднородность обязательна: нельзя считать PBR готовым при одних только числовых roughness/metalness и сплошной заливке.
- **Цвет:** глубокий чёрный, сине-серый и графитовый доминируют; небольшие янтарные окна и фонари; бело-холодный прожектор. Никаких ярких кислотных цветов, дневного неба, мультяшного контраста.
- **Композиция:** низкая камера, выраженная точка схода, поезд не заполняет весь кадр, большая доля негативного пространства занята атмосферным небом и светом; передний план детализирован и частично перекрывает средний. Для 9:16 сохранять драматическую диагональ луча и рельсов.
- **Никакого лишнего:** добавлять только элементы, видимые на референсах или необходимые для их достоверной реализации; не заменять художественную задачу UI, новыми режимами, эффектными кнопками, дополнительными просмотрщиками и не относящимся к кадрам геймплеем.

### Порядок визуальной приёмки

1. Референсы R1/R2/R3 **загружены в GitHub** (720 × 1280, уменьшенные копии оригиналов); обязательная карта фактических файлов и идентификаторов приведена в `REFERENCE_FRAMES_R1_R2_R3_RU.md`. До сравнительных игровых кадров статус художественной приёмки моделей остаётся **NOT VERIFIED**.
2. Собрать **одну** настоящую контрольную сцену R1 с поездом, рельсами, платформой, ветвями, дождём, туманом и освещением; затем R2 и R3. Не объявлять три изолированные модели полноценной сценой.
3. Для каждой сцены снять игровой кадр с тем же вертикальным соотношением 9:16 и сопоставимым ракурсом. Сравнить рядом с соответствующим эскизом: силуэт, положение поезда, геометрию пути, направленность и мягкость луча, плотность тумана, тональные массы, отражения и детализацию переднего плана.
4. **Художественный gate — обязательный блокер:** если любой ключевой признак отсутствует, объект/сцена остаётся WIP независимо от числа полигонов, файлов, анимаций и формальной валидности JSON. Процент качества без сравнительных кадров не подтверждён.
5. Прежде чем масштабировать производство до 640 позиций, добиться принятого визуального качества одной контрольной сцены. Следующие ассеты наследуют именно её утверждённые материалы, масштаб детализации, свет и художественный язык.

# META GAMES — проверяемая готовность на 07.11.2026

## Результат повторной независимой проверки

| Подсистема | Проверенные критерии | Готовность по 10 критериям |
| --- | ---: | ---: |
| MCP | 2 / 10 | **20%** |
| Библиотека решений | 4 / 10 | **40%** |
| Бот-проходчик и автоисправления | 1 / 10 | **10%** |
| **Среднее** | **7 / 30** | **23%** |

**Методика:** ровно десять заранее записанных бинарных критериев на подсистему, равный вес. Не подтверждено = 0; открытый PR = 0; частичный успех = 0. Это *доля выполненных критериев*, не точная оценка трудоёмкости или прогресса к релизу. Файл `meta-games/readiness/gates.json` содержит определения, статусы и ссылки. `score.json` генерируется проверяющим скриптом, а не редактируется «на глаз».

4. Прежние **63% общей готовности** были субъективным средним. **Исправлено на 23%** по открытой шкале 30 критериев. Изменение процента отражает прежде всего исправление методики, **не деградацию работающего кода**.

## Что реально улучшено сейчас

- В отдельной ветке `lab/readiness-evidence-gates` введены критерии приёмки с URL и состоянием для каждой подсистемы.
- `scripts/lab/readiness-audit.mjs` проверяет структуру, уникальность критериев, дату и **статус merged для всех PR, которым присвоен PASS**. Открытый PR не может увеличить готовность.
- CI `LAB Evidence-Based Readiness` отклоняет устаревший или вручную завышенный `score.json`.
- Отдельно сохраняются три значения: **реализовано в ветке**, **принято в sandbox main**, **доступно в production**. В процентах учитываются только критерии, чьё конкретное условие действительно выполнено; наличие кода в ветке не равно production.
- Для функционального PASS по-прежнему требуется отдельная проверка связанного Actions и игрового результата: факт merged **не доказывает** правильность поведения, поэтому проверяющий скрипт нельзя считать полной независимой экспертизой.

## Оставшиеся блокировки

- Публичный write-enabled MCP с авторизацией, проверенными исходниками и фактическим production smoke.
- Интеграция двух оригинальных общих модулей хотя бы в одну игру; утверждение об экономии времени и токенов только после измерений.
- Полный бот-проход остальных эталонов и реальный случай «сбой → исправление → повторный полный PASS → безопасная публикация».

**Правила дальнейших обновлений:** не повышать проценты без изменения конкретного критерия и проверяемого подтверждения; не считать unmerged PR или запуск с `action_required` зелёным; фиксировать отдельно SHA, Actions, upstream-права, подтверждение владельца и статус деплоя; при неясности ставить pending; запрещено записывать автоматически принятый результат, если бот или владелец его не подтвердили. Основной `mpaykin1/meta6` не изменён.

## Повторная самопроверка: исключение ошибок в отчёте

- Код проверяющего скрипта усилен: только три доверенных репозитория, PR должен быть слит именно в указанном репозитории и не позже времени проверки; дата и возраст данных ограничены.
- CI теперь сравнивает **не только score.json с gates.json**, но и проценты в опубликованном REPORT.md. Несовпадение автоматически блокирует принятие.
- Добавлен ежедневный запуск независимой проверки **после принятия workflow в default branch**; в открытом PR расписание ещё не действует.
- Самопроверка выявила ограничение: merged PR — доказательство интеграции кода, но не функционального успеха. Проценты не повышались без нового подтверждённого критерия.
- Текущая ветка и отчёт: [lab/readiness-evidence-gates / PR #16](https://github.com/mpaykin1/meta6-lab/pull/16). **PR открыт, в main не слит.** Поэтому сама система аудита пока считается экспериментальной, а не production-функцией.

# БИБЛИОТЕКА ИГР — ОБЯЗАТЕЛЬНЫЙ ЦИКЛ ИСПРАВЛЕНИЯ

1. При каждом запуске прочитать `AGENTS.md`, `ZADACHI.md`, `BIBLIOTEKA.md`, текущий PR библиотеки и последние коммиты. Продолжать существующую ветку; не дублировать PR.
2. Первый незакрытый пункт исправить кодом, а не только описанием. Каждый запуск должен завершаться хотя бы одним сохранённым улучшением, если запись в GitHub доступна. Не утверждать «исправлено» без SHA и результата проверки.
3. Библиотека предназначена для MCP и ИИ, не для пользовательской витрины. Системы брать только из оригинальных игр, без переписывания работающей графики. `*-copy` не являются эталонами; защищённые файлы не удалять.
4. Для каждого исходного фрагмента: Acorn AST и полный синтаксический узел, оригинальные байты и SHA, зависимости, отдельный Chromium-контекст, корректный `type=module` и версия THREE оригинала. `load_ok=true` только после реального браузерного запуска. Неисполнимое отдельно сохранять с `standalone=false` и точной причиной.
5. `asset_ids` заполнять только по реальным ссылкам исходного кода. Неоднозначные ссылки не угадывать; учитывать как `unresolved_assets`. Загрузка моделей, текстур и звуков должна подтверждаться независимо.
6. `BIBLIOTEKA.md` должна совпадать с `catalog-solutions.json` и `index.json`; числа без закреплённой ссылки на SHA недействительны. Обязательны мутации: все `load_ok=false`, отсутствующие `asset_ids` при реальных ссылках, `*-copy` как эталон, неверная цифра в таблице.
7. Проверять реальный `canvas` в Chromium после сборки через MCP из трёх систем разных игр. Непустой canvas и отсутствие ошибок обязательны; наличие только инструментов MCP не является успехом.
8. Красный CI: сначала установить упавший шаг и первопричину, затем исправить в той же ветке и добавить ловушку. Не обходить проверку, не подменять результат и не ставить зелёный вручную.
9. После каждого исправления: push в существующую ветку, обновить прогресс в `BIBLIOTEKA.md` отдельным небольшим коммитом в main; зафиксировать SHA в PR. При ожидающем CI не выдавать работу за слитую.
10. Не изменять `scripts/zadachi/`, `.github/workflows/zadachi-watch.yml`, `rules/09-platforma/FINISH*.md`; `meta6` только чтение. Работать бесплатно.
11. Финальный ответ: только что ещё не готово, фактические счётчики со ссылками и последняя ссылка на `BIBLIOTEKA.md`. Нельзя завершать запуск одним анализом: последним действием должно быть реальное изменение и push, а не обещание.

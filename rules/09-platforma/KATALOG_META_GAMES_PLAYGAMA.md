# META GAMES — обязательные правила обновления каталога Playgama

**Решение владельца от 17.11.2026.** Относится к публичному каталогу [META GAMES](https://mpaykin1.github.io/meta6/playgama-catalog/) и ко всем его языковым версиям. Не путать с отдельным каталогом игр без рекламы в МГЛ.

## 1. Главное: ОДИН КЛИК = ИГРА НА PLAYGAMA

1. Нажатие на **обложку, название или кнопку «Играть»** каждой игры сразу открывает **её настоящую игровую страницу Playgama**, по прямому адресу `https://playgama.ai/play/<siteId>`. Все три ссылки одной карточки ведут на **один и тот же URL**. Внешние ссылки открываются с `target="_blank" rel="noopener noreferrer"`, как в действующем каталоге.
2. **Запрещены промежуточные страницы:** `playgama-catalog/games/<slug>/`, «Подробнее», «Выбрать, где играть», дубли игры на META GAMES, переход через собственное превью, выбор платформы. В каталоге не предлагать альтернативную версию для игры вне Playgama.
3. Для новой игры правило действует **на всех языках**, включая переход по клику на изображение, а не только по кнопке Play. Кнопка деталей для новых карточек не нужна. Удалять из Sitemap страницы-посредники; сами файлы-посредники не создавать.
4. **Никогда не выдумывать siteId, адрес, статус модерации или готовность игры.** Сначала искать точную ссылку в кабинете Playgama, README соответствующей игры и других подтверждённых источниках, затем проверять, что она ведёт к нужной игре. Если реальный URL не найден или запуск недоступен — не выдавать непроверенную карточку за играбельную и не подменять прямой запуск страницей описания.
5. Различать **DRAFT / ACTIVE sandbox / VISIBLE / опубликовано в каталоге Playgama**: один статус не доказывает другой. На странице и в метаданных не утверждать неподтверждённое.

## 2. Добавление новой игры

1. Сначала читать свежий `mpaykin1/meta6/main`: `AGENTS.md`, `playgama-catalog/playgama-inventory.json`, исходники каталога, актуальный список игр в Playgama. Истина — GitHub и подтверждённая ссылка, не память чата.
2. **Новую игру ставить первой**, если владелец не указал иного. Прежние игры сохранять в неизменном относительном порядке: ничего не удалять и не переименовывать самовольно, не добавлять дубль.
3. **Индивидуальная обложка обязательна.** Использовать официальную обложку Playgama или изображение, предоставленное владельцем, сохранить без подмены чужим артом. Обложка корректно отображается на мобильном и ПК, пропорции сохраняются; `alt`, размеры, `loading` и приоритет первой картинки осмысленны.
4. У карточки: точное название, жанр, **правдивое** краткое описание на языке страницы и прямой Playgama URL. Не выдумывать механику по одной картинке. Сведения об игре брать из исходника/README/страницы игры; о непроверенном писать как о непроверенном.
5. Обновлять `playgama-inventory.json` без потери существующих `games`, `pendingGames`, `sandbox.url`, `coverUrl`, статусов и подтверждений. Существующий `pendingGames` не выдавать за подтверждённую публикацию. Не переписывать инвентарь целиком и не менять старые игровые ссылки «заодно».
6. Список и количество карточек, порядок и JSON-LD `ItemList` должны совпадать. **Счётчики пересчитывать по фактическим карточкам**, а не оставлять старые «14»/«15»; слово «играбельные» использовать только для игр с подтверждённым запуском.

## 3. Все языки синхронно

Поддерживаемые главные страницы:
- `playgama-catalog/index.html` — EN
- `playgama-catalog/ru/index.html` — RU
- `playgama-catalog/de/index.html` — DE
- `playgama-catalog/fr/index.html` — FR
- `playgama-catalog/ja/index.html` — JA
- `playgama-catalog/ko/index.html` — KO
- `playgama-catalog/es/index.html` — ES
- `playgama-catalog/pt-br/index.html` — PT-BR

При добавлении, удалении или перестановке игры **обновить все 8 главных страниц в одной задаче**. Одинаковы набор игр, порядок и URL запуска; на каждом языке локализованы видимые тексты, `alt`, метаописание. Не смешивать языки. Если меняется классификация — обновить соответствующие локализованные `genres/*` без вымышленных игр. Отдельная страница лора `lore.html` в каждой локали остаётся доступной: её переход не является переходом по карточке игры.

## 4. SEO без дублирования и выдумок

1. Для каждой локали: собственные `<html lang>`, `title`, `meta description`, self-`canonical`, `og:title`, `og:description`, `og:image`, Twitter Card. На страницах жанров и лора — собственные уникальные канонические URL.
2. В `application/ld+json` (`CollectionPage`, `ItemList`, `VideoGame`, где применимо) **количество и позиции** совпадают с видимым каталогом; у игр правильный прямой URL Playgama. Не размечать как активную/опубликованную игру без подтверждения.
3. Проверить взаимные `hreflang` для реально существующих языковых версий и `x-default`. В `playgama-catalog/sitemap.xml` — только настоящие индексируемые страницы; страницы-посредники для игр запрещены. `lastmod` менять, когда содержание действительно изменилось. Прямые внешние страницы Playgama в sitemap META GAMES не включать.
4. **Лор под ENTER THE DREAMVERSE:** у каждого языка свой отрывок «Зерно последнего мира», кликабельный переход к **полной истории на том же языке**. Лор не заменять рекламным описанием при очередном обновлении каталога.
5. SEO-изменения не должны менять логику игр, оригинальные ассеты или рекламные настройки. Для META GAMES-веб игр — правило «БЕЗ РЕКЛАМЫ»; внешнюю рекламу Playgama контролирует сама площадка.

## 5. Обязательная приёмка и публикация

Перед завершением:
- Открыть все 8 карточек новой игры: **обложка / заголовок / Play ведут непосредственно на тот же `playgama.ai/play/…`**. Ни одного href на `playgama-catalog/games/<slug>/` у игровой карточки.
- Убедиться, что все старые игровые ссылки и порядок сохранены, новая обложка отображается, сайт удобен на телефоне и ПК, отсутствуют лишние кнопки и промежуточные страницы.
- Сверить реальные числа карточек, позиции JSON-LD и счётчики; `canonical`, `hreflang`, Sitemap, ссылки на лор. Никаких ложных заявлений о статусах Playgama.
- После разрешённой публикации проверить **HTTP 200** точного каталога, изображение и Sitemap, фактический переход по новой карточке и успешный GitHub Pages deploy. Коммит/PR сам по себе не доказывает публикацию.
- При найденной ошибке — исправить её и закрепить правило, чтобы не повторялась. **Запрещено ослаблять охранников**, менять защищённые эталоны, добавлять платные сервисы.

# Рецепт №1 — ЧИСТЫЙ ЭКРАН (не означает внедрения в игру)

Источник правила: [CHISTYY_EKRAN.md](../../01-stil-i-grafika/CHISTYY_EKRAN.md), [RULES_CHECKLIST.md](../RULES_CHECKLIST.md), строка №1. Существующий игровой образец: `games/broken-city/` (см. «Статус по играм»). При заимствовании сначала прочитать исходник целиком и зафиксировать точный SHA; не переносить код по памяти.

## Перед изменением

1. Прочитать `automation/uluchshatel/PROGRESS.md`, `ZADACHI.md`, `ZANYATO.md` и **все** открытые PR с их изменёнными файлами (включая переименования и пагинацию). Если за 60 минут был коммит по игре, есть чужой захват либо ошибка GitHub API — игру не трогать.
2. Тренировка — только свободный `games/skin-trainer` или уже существующая `games/*-copy`. Новые копии не создавать; эталоны и существующие защищённые игры не сливать.
3. Прочитать `REUSE.md`, `META_GAMES_SOURCE_ALLOWLIST.md`, `NE_MENYAT_NEZAPROSHENNOE.md`, `PERECHEN_OBEKTOV.md`, `BEZ_REKLAMY.md`; снять опись реальных ассетов, уровней, механик и звуков скриптом из исходного кода и сохранить `docs/INVENTORY_<игра>.md`.
4. Записать FPS p95 и прохождение ботом **до** правки. Если живых замеров нет, статуса «сделано» не будет.

## Как внедрить

1. Оставить игровой экран за 3D/2D-графикой и **кнопками-пиктограммами**. У каждой кнопки обязательный `aria-label`; текстовые названия, счётчики и подсказки перенести в **уже существующее** меню, не уничтожая данные. Кнопка ☰ — справа сверху.
2. Загрузочный экран без текста, ошибки запуска допускаются отдельно. Состояния показывать имеющимися графическими сигналами: свечением, кольцом заряда, меткой мира. Не заменять принятые владельцем анимации, управление, камеру или физику.
3. Короткие сообщения об открытии, речь героя и подписи-воспоминания **сохранить**; они должны реально исчезать. Придуманному `class="fade"` или `setTimeout` без проверки видимого результата не доверять.
4. `skipChecks=[]`; не ослаблять `scripts/meta-bot/checks.mjs`. Если проверка каркаса отвергает гаснущие сообщения, указать «ждёт правки каркаса: гаснущие сообщения»; это не основание удалять память/диалоги.
5. Ассеты не удалять. Сверить фактические описи: «было N → осталось N, потеряно 0». Реклама и SDK в META GAMES запрещены.

## Как подтвердить

- Аудитор `scripts/uluchshatel/clean-screen-audit.mjs` принимает **реальные** снимки DOM из браузера: время, стабильный id, видимость, текст, роль/тег, `aria-label`, состояние меню и координаты кнопки. Для динамических сообщений нужна серия кадров как минимум до **6 секунд после их появления**.
- Команды: `node scripts/uluchshatel/verify-clean-screen-audit.mjs` и `node scripts/uluchshatel/mutate-clean-screen-audit.mjs`. Проверка включает четыре мутации, среди них обман «CSS-класс обещает исчезновение, но надпись остаётся».
- В реальной игре отдельно инспектировать текст, нарисованный **в canvas/WebGL**, поскольку DOM-аудитор его не видит. Убедиться, что закрытое меню не протекает на экран, а кнопки на ПК и телефоне 390×844 остаются функциональны.
- Снять одинаковые действия/кадры до и после, FPS p95 на телефоне и ПК, бот-прохождение, verify/mutate на GitHub Actions при **точном HEAD SHA**. Без зелёных Actions + живых браузерных измерений правило **не** переводить в «сделано».
- Нужна подпись Claude для слияния защищённых путей. Только владелец ставит PASS/FAIL.

## Частые ошибки

- Постоянный HUD просто получил CSS-класс `fade` → проверять **видимые** кадры через 6 секунд.
- Исчезли подписи-воспоминания → откатить такое изменение; каркас бота правит Claude, не игра.
- Кнопка стала иконкой без `aria-label` → ошибка доступности.
- Меню визуально скрыто, но его текст продолжает быть видимым → проверять фактический computed style, родителей и геометрию.
- На пустой DOM-проверке забыли о тексте, рисуемом Canvas → дополнительная браузерная визуальная проверка обязательна.

## Как внести

1. Прочитать `automation/uluchshatel/PROGRESS.md`, `ZADACHI.md`, `ZANYATO.md` и все открытые PR с путями файлов; если в игру писали за 60 минут или есть пересечение — не захватывать.
2. Снять опись **из исходного кода**, сохранить `docs/INVENTORY_<игра>.md`: реальные ID, количество зарегистрированных оружий, врагов, уровней, звуков, шейдеров и ассетов. Внести «было N → осталось N, потеряно 0».
3. В новой JS-обёртке только читать существующее состояние уровня и героя. `window.__META_BOT__` должен содержать `info()` и `state()`, возвращать `stage`, `stagesTotal`, `level`, `hero`, `goal`, `alive`, `levelDone`, `gameDone`, `buttons`, `progress`. Координаты героя и цели — **реальные x, y, z**, а не заглушки. Цель до победы не должна быть `null` или отсутствовать. Прохождение/смерть/видимые кнопки — по фактическому состоянию.
4. У интерфейса **нет метода движения героя**; вызов `state()` не меняет игровое состояние, не пишет `G`, не телепортирует и не вызывает игровых функций. Публиковать объект через `Object.freeze` и `Object.defineProperty` с `writable:false`, `configurable:false`. Исключить специальные случаи по CI/тестам.
5. Подключать наблюдатель **после** создания игрового состояния. Сверить оригинальный HTML побайтно после удаления только нового `script`-тега; все ассеты сохранены. `skipChecks=[]`; гаснущие сообщения сохраняются; рекламный код не добавлять.
6. `verify-*.mjs` проверяет живые координаты, отсутствие побочных эффектов, цель после подбора предмета, смерть и победу, активные кнопки, побайтную целостность источника. `mutate-*.mjs` проверяет минимум три ошибки, включая **обман** жёстко заданными координатами; все мутации обязаны падать.
7. Прогнать Node-проверки и GitHub Actions на текущем SHA, затем браузер ПК и телефон 390×844 с тачем, FPS p95 до/после и полноценный META BOT. До зелёных verify + mutate и браузерного прогона **не отмечать правило «сделано»**, не писать OWNER PASS/FAIL.
8. Изменение защищённой игровой папки — только отдельный PR «НУЖЕН CLAUDE», без самостоятельного merge. После зелёных Actions предложить Claude одобрение, внести ссылку на Actions run в `RULES_CHECKLIST.md` и `DLYA_CLAUDE.md` по правилам владельца.

## Конечная цель — из условий настоящей победы

Для `sumerki-i-pepel-2-copy` взять штатную `nearestGoal()` из оригинального HTML: до сбора всех монет — ближайшая живая монета; при `G.all` и живом `G.warden` — `G.warden.segs[0]`; после победы над стражем — `world.ring`. `world.beacon` — визуальный маяк, но достижение его координат не завершает уровень. Проверка обязана пройти все три перехода, включая исчезновение стража. Мутация подмены `world.ring` на `world.beacon` обязана падать.

## Частые ошибки и предотвращение

- Использовали координаты `(x, z, z)` вместо `(x, y, z)` → отдельная проверка вертикальной координаты `hero.y`.
- Задали цель `null` или неизменяемую заглушку → проверка ближайшей живой цели и перехода к следующей.
- `state()` незаметно меняет счётчик врагов, положение героя или любой объект игры → сериализовать состояние до/после и сравнить.
- Проверка проходит только со статическими данными из fixture → мутация-обман подставляет константы.
- Появился «зелёный» статус без Actions/реального браузера → считать не подтверждённым, оставлять пару в очереди.

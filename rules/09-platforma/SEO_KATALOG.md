# SEO каталога META GAMES — обязательные правила

Применяется к каталогу «17 игр без рекламы» и будущим индексируемым страницам МГ/МГЛ. Выполнять совместно с AGENTS.md, FINISH.md, КОНТУР К1–К12, ЧИСТЫЙ ЭКРАН и правилом ССЫЛКА = 200. Бесплатные инструменты; существующие рабочие механизмы переиспользовать.

## 1. Адреса и индексация
1. Постоянный адрес каталога МГЛ: `https://mpaykin1.github.io/meta6-lab/claude-games/` — **целевой**, но считать опубликованным только после фактического HTTP 200. Для МГ брать только реально утверждённый постоянный адрес, не копировать адрес МГЛ.
2. Canonical, og:url, Schema.org URL и sitemap должны совпадать с выбранным постоянным адресом каждой страницы. Для полностью дублирующих версий указывать canonical основной страницы.
3. Любые временные preview — `<meta name="robots" content="noindex,nofollow">`; не включать preview в sitemap/IndexNow. Не блокировать их robots.txt так, чтобы робот не мог увидеть noindex.
4. Не публиковать URL, который ведёт на 404, перенаправление на рекламу, внешнюю игру вместо заявленной собственной или неработающую сцену.

## 2. Контент 17 игр
1. У каждой самостоятельной игры — уникальный title не длиннее 60 символов и meta description 120–160 символов; естественные названия, без повторов ключевых слов.
2. У каждой игры — содержательное оригинальное описание 150–300 слов: сюжет/действия, отличия от соседних игр, **проверенное по самой игре** управление ПК и телефона. Не выдумывать механику и поддержку устройства.
3. Три видимых полезных FAQ, отражающих факты страницы; FAQPage JSON-LD с корректными Question и acceptedAnswer. Разметка не обещает показ расширенных результатов в поиске.
4. Для четырёх сумеречных островов и двух Broken City описывать подтверждённые различия. Если версия фактически дублирует другую — canonical на основную вместо искусственного уникализирования.
5. На каждой странице 2–3 **реальных** собственных WebP-скриншота с осмысленным alt; уникальная локальная OG-обложка. Не использовать static.playgama.com как источник обложек, не делать preconnect к нему. Не заменять настоящие кадры синтетическими изображениями под видом скриншотов.
6. Внутренняя перелинковка по жанрам, похожим играм, лору и каталогу; ссылки проверять. Лор и игра должны вести к существующим локальным страницам.

## 3. Техническая проверка
1. Валидировать JSON-LD разбором JSON и обязательные поля, согласованность canonical/og:url/Schema.org, title, description, alt, robots, hreflang при наличии и sitemap.
2. Проверять внутренние ссылки на существующие файлы в PR и реальные HTTP 200 после публикации. Не считать успешный CI доказательством доступности опубликованного сайта.
3. Sitemap включает только живые индексируемые URL; lastmod — дата фактического последнего содержательного изменения файла из Git, не текущая дата сборки.
4. IndexNow: ключ и keyLocation размещены на том же доступном хосте; отправлять только изменённые опубликованные URL после успешного деплоя; перед отправкой проверить HTTP 200 ключа и страниц, затем статус API 200/202. IndexNow не гарантирует индексацию Google.
5. Новые проверки — с минимум тремя мутациями, включая обманную; существующие охранники, эталоны, hash и бот-контракт не ослаблять. Workflow только если нельзя дополнить существующий; соблюдать paths, concurrency и timeout-minutes.
6. Следить за загрузкой: локальные оптимизированные изображения, явные размеры, lazy-loading ниже первого экрана, без лишних запросов к сторонним ресурсам; первый экран и игра остаются видимыми и отзывчивыми.

## 4. Публикация и продолжение
1. Не менять исходники защищённых эталонных игр ради SEO. Игровые исправления — отдельно и с обязательными проверками.
2. Не сливать красный PR. Слияние и публикация только по правилам репозитория; точный живой URL проверить HTTP 200 и наличие SEO-тегов в опубликованном HTML.
3. Продолжать с первого незавершённого пункта `progress/seo-claude-games.json`, фиксировать изменения коммитами в ветке; завершённые шаги не повторять.
4. После основной работы каждый прогон — минимум одно полезное измеримое улучшение: контент, реальные кадры, внутренняя перелинковка, скорость, локализация или проверка. Идеи сохранять в progress.
5. Каждое «готово», «зелёное», «слито», «опубликовано», «IndexNow принял» подтверждать конкретным SHA/PR/Actions/живым HTTP ответом. Задачи учитывать в общей ZADACHI.md без дублей.

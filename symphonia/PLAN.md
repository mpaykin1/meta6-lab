# SYMPHONIA — «Симфония тьмы» — ПЛАН ДЛЯ 5 АВТОЗАДАЧ (читать каждый запуск)

Утверждено владельцем 24.11.2026. МГ (META GAMES) больше не развивается — все 5 автозадач работают только на SYMPHONIA.
Этот файл — единственная инструкция. Автозадачи читают его заново каждый запуск, поэтому при изменении плана перенастраивать их не нужно.

## 0. Игра в двух словах
Мир, где музыка меняет реальность. Героиня — музыкант, игрок — её защитник. Пока она играет, рождается красота и вместе с ней чудовища.
Каждое действие игрока — часть произведения: удары = ритм, победы меняют гармонию, ошибки = диссонанс, спасение героини очищает мелодию. Чем жестче игрок, тем страшнее музыка и уродливее мир.
Технологии: Three.js + GLSL + sprite stacking, своя процедурная музыка на WebAudio. Только бесплатное.

## 1А. ЭТАЛОНЫ — быстрая загрузка (владелец, 24.11.2026)
- Эталон (игра, сцена, набор ассетов) загружается **как есть**: файлы копируются без сборки и без улучшений. Улучшения — отдельным PR потом.
- Один эталон = одна новая папка, которую не меняет ни один открытый PR (иначе бот «ОДИН PR НА ДЕЛО» закроет PR).
- Без дублей: каждый файл ассета лежит один раз; не класть рядом «собранную» копию игры со встроенными картинками.
- Чужие библиотеки (three.js и т.п.) не копировать в репозиторий — подключать с CDN.
- PR эталона сливается сразу, как только проверки зелёные (обычно 4–5 минут).
- Автоматически для каждого эталона: если в его папке есть `bots/bot_*.py`, на каждом PR их запускает проверка ETALON BOTS (`.github/workflows/etalon-bots.yml`); замер телефона (`telefon-bez-tormozov`) и открытие без ошибок (B1) идут для всех игр сами. Новый эталон игры с `window.__bot` кладётся вместе с ботами — образец `symphonia/game/bots/`.

## 2. ГЛАВНЫЙ ЗАКОН — один хозяин у файла игры
- `symphonia/game/` меняет **только Скилы-5**.
- Скилы-1…4 пишут только в свою папку `symphonia/modules/<папка>/` (§3). Там лежат JS-модуль, его данные (JSON) и `README.md` с описанием, как подключить модуль.
- Чужую папку не трогать. Так автозадачи не ломают работу друг друга.

## 4. ШКАЛЫ — главная механика в числах (общие для всех модулей)
Один общий объект состояния `window.SYM_STATE` (каждый модуль только читает его и сообщает события, но не создаёт свой):
- `garmoniya` 0–100 — растёт от точных ударов в такт и от спасения героини, падает от промахов.
- `zhestokost` 0–100 — растёт от лишних, добивающих и жестоких действий. Делает музыку мрачнее, мир уродливее, монстров злее.
- `chistota` 0–100 — чистота мелодии героини. Падает, когда она получает урон, растёт, когда игрок её защищает.
- `glava` — номер текущей главы, `takt` — текущая доля такта.
От шкал обязаны зависеть музыка, свет, поведение монстров и концовка. Заявление «действия меняют музыку» засчитывается, только если бот видит, что значения шкал меняют звук или картинку (§5).

## 5. БОТЫ — перед каждой публикацией, 0 ошибок
Скилы-5 держит их в `symphonia/bots/` и запускает через Actions (workflow `symphonia-check.yml` создаёт сам, если его нет):
1. Бот-проходчик проходит все открытые главы до конца. Герой не должен застревать или умирать без причины.
2. Бот шкал меняет шкалы §4 и проверяет, что меняются громкость или тон музыки и цвет или свет кадра.
3. Бот формы главы проверяет: в Вальсе враги ходят на доли 3/4, в Фуге голоса вступают по очереди, в Токкате атаки идут без пауз и т.п.
4. Телефон: `node scripts/telefon-bez-tormozov.mjs symphonia/game/index.html` (правило ТЕЛЕФОН БЕЗ ТОРМОЗОВ).
5. iPhone: прогон в WebKit-эмуляторе iPhone с занятыми глобальными `t, P, g, W, H`. Код игры обёрнут в свою функцию. Звук стартует по первому касанию.
6. ЗВУК: диссонанс звучит в 2 раза тише гармонии, нет резких и пронзительных звуков, музыка развивается.
7. ЧИСТЫЙ ЭКРАН: в игре нет видимого текста, кроме меню ☰ в правом верхнем углу.
Бот упал — Скилы-5 исправляет сам и только потом публикует. Старую рабочую версию не заменять сломанной.

## 11. ГЛАВНАЯ РАБОТА — новые sprite stacking ассеты каждый час (владелец, 24.11.2026)
Автозадачи работают круглосуточно. **Каждый запуск каждой роли создаёт минимум 1 новый sprite stacking ассет в стиле игры, и игра расширяется.**
- Стиль: сначала прочитать `symphonia/assets/STIL.md` и посмотреть эталоны `assets/claude-etalon/`; генератор `symphonia/tools/sprite_stack.py`. Призрачный, тонкий, почти прозрачный, как зал «Адажио». Тёмная палитра, свечение, туман, музыкальные мотивы (струны, клавиши, ноты, трубы органа).
- Формат: `symphonia/assets/<роль>/<имя>/`: `slices.png` (стопка срезов снизу вверх в одну полосу), `asset.json` (число срезов, размер, анимация срезов, к какой главе относится) и `preview.gif` (вращающийся ассет на прозрачном фоне, чтобы владелец сразу его видел). Срезы можно рисовать кодом один раз при сборке. Рисует игра через Three.js: стопка плоскостей или инстансы, без попиксельных циклов на процессоре в кадре.
- Ассеты живые: срезы колышутся по синусоиде, свечение пульсирует в такт музыки (шкалы §4).
- Что делает каждая роль:
  - Скилы-1 — «звучащие» объекты: инструменты, органные трубы, метрономы, люстры-колокольчики. Каждый ассет звучит своей нотой.
  - Скилы-2 — монстры и персонажи (по главам), враги со своим ритмом движения.
  - Скилы-3 — архитектура и локации глав: колонны, лестницы, окна, двери, ожившие стены.
  - Скилы-4 — атмосфера и эффекты: ноты-призраки, туманные силуэты, световые столбы, частицы.
  - Скилы-5 — встраивает все новые ассеты в игру по главам (правило ПОСТЕПЕННО: открываются победами), гоняет ботов §5, публикует и обновляет витрину ассетов `symphonia/assets/index.html`.
- БЕЗ ПОВТОРОВ: перед созданием проверить `symphonia/assets/SPISOK.md`. Новый ассет отличается от всех прежних формой, силуэтом и движением. Каждый новый ассет — строка в SPISOK.md.
- Ассет без `preview.gif` или без строки в SPISOK.md не засчитывается.
